\section{Reproducibility and Audit Trail}
\label{app:repro}

\paragraph{Decision log.} The admission thresholds used in Section~6 were recorded in
the project decision log before any 151-item outcome existed: the v6 entry
(2026-08-31) set a 20\% union-repair threshold; the v7 entry (2026-09-01), which fixed
the evaluation set at 151 items, records ``union repair $\geq$15--20\%'' while the
same-day experiment plan specifies $\geq$15\%. We operationalize $\geq$15\% and
disclose that both readings admit the same populations (C6 at 21.6\%, D6 at 24.3\%)
and leave all other admission decisions unchanged. The repository history is
initialized retrospectively (2026-09-03); file mtimes and the decision-log changelog
are the authoritative ordering record.

\paragraph{Data hygiene.} 24 of 151 evaluation items overlap day-1 protocol-development
runs; the A-arm population selection used only the 36 fully disjoint items. The bare
baseline flipped 3 of 60 items between the two day-1 runs (API nondeterminism at
temperature~0), so 60-item columns are conditioned on slightly different bare-error
sets.

\paragraph{Generation provenance.} The 09-01 free-form populations (conditions C, D)
were produced in-session; their generation tool was not preserved. The tool of record
from 2026-09-03 (\texttt{builder\_generate3.py}) logs every attempt (3 retries,
16{,}384-token budget, per-attempt stage and finish reason) and accepts a candidate
only after it imports against both databases and solves one builder-visible question.
The GLM condition-B population reported in Section~6 is the logged re-run.

\section{Generation and IR Specifications}
\label{app:specs}

\paragraph{Strategy-forced free-form prompt.} Builders receive the \texttt{SQLHarness}
interface, one strategy description sentence, and the required class name; the full
prompt template, per-strategy descriptions, and the six per-builder acceptance logs
are released verbatim.

\paragraph{Harness IR.} A spec is a typed record:
$\text{context} \in \{\text{plain}, \text{schema\_link}, \text{hint\_guard}, \text{link+hint}\}$,
$\text{generate.candidates} \geq 1$ with temperature,
$\text{execution.execute\_each} \in \{0,1\}$,
$\text{repair}.\{\text{on\_error}, \text{max\_rounds}\}$,
$\text{selection} \in \{\text{first\_ok}, \text{majority\_rows}, \text{llm\_judge}\}$.
The compiler emits deterministic Python from fixed templates.
