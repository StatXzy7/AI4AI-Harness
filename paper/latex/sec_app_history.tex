\subsection{Early generation-protocol probes and their limits}\label{sec:phase1probes}
Phase I also probed generation-side fixes --- a strategy-forced free-form protocol
(assigned mechanism, import/smoke acceptance) and a compiled Harness IR. Under the
strategy-forced protocol two of three builders produced populations whose point
estimates exceeded the pre-specified thresholds (Qwen3.8-Flash 5.96,
DeepSeek-V4-Flash-Vision-Exp 7.95\,pp; the old-protocol arm missed at
4.64\,pp), and per-strategy acceptance ordered with builder identity
(GLM-5.3-Flash 3/8, Qwen3.8-Flash 7/8, DeepSeek-V4-Flash-Vision-Exp 8/8,
under the logged tool). These
observations motivate Phase II but are not confirmatory, for three disclosed reasons:
the design was two nested contrasts that cannot separate protocol from builder main
effects; the early runs lack per-attempt logs, so budget equality cannot be audited;
and acceptance was an import/smoke check, not the counterfactual conformance gate of
\S\ref{sec:f2-admission}. Full condition details are in Appendix~\ref{app:phase1-provenance}.

\paragraph{Generation-null failures (M0).} Re-running the original optimize loop
with Qwen3.8-Flash and DeepSeek-V4-Flash-Vision-Exp builders produced 40 candidates byte-identical to the
\bare{} baseline source. Code identity alone does not imply identical stochastic
executions. This run supplies no distinct-code population; it is reported as a distinct,
more primitive failure mode --- the pipeline produced no distinct population at all.
The collapse claims above rest exclusively on the genuinely distinct-source discovery
population.

\paragraph{Figure data.} Figure~\ref{fig:phenomenon} compares source
similarity with correctness disagreement for the observed harness pairs.

\paragraph{Fixed historical record limits.} The early free-form
populations were produced in-session. Their generation tool and
per-attempt logs were not retained, leaving budget equality
unrecoverable from these historical records. Their acceptance was an
import/smoke check at evaluation time. The subsequent logged generation
procedure used at most three attempts, a 16{,}384-token budget, and
per-attempt stage and finish-reason records. The completed per-strategy
grids and builder-acceptance ordering (3/8, 7/8, 8/8) come from that
logged procedure and were analyzed after the admission decisions were
frozen.

\subsection{Upstream code-extraction audit}\label{app:extraction}
Across the 36 forced C/D cells, all 108 \texttt{format\_guard} attempts
failed neutral validity: 71 logs report unterminated Python strings,
36 report no Python fence, and one reports a provider timeout.
The archived generator's non-greedy Python-fence extractor terminates at
the first subsequent triple backtick, including one inside a Python
string. Three synthetic, syntactically valid programs containing SQL fences
in an ordinary string, docstring, or regex become invalid prefixes;
the extractor nevertheless sets its truncation flag to false.
The audited extractor matches the retained implementation, but the
historical attempt records do not verify which version actually ran. Full builder messages
were not saved by this generator; this is a fixed historical record
limit. The synthetic examples establish the extractor's truncation
behavior, while the historical pattern is compatible with the same
failure mechanism.
We found 74 retained extracted programs, all syntactically invalid; three
coexist with no-fence logs and are retained as provenance conflicts,
not attributed to those attempts. These findings place a generation
interface failure alongside the gate's explicit strategy exclusions.



\subsection{Historical BIRD selection analyses}\label{app:rich}
This selection analysis and the fingerprints in
Appendix~\ref{app:bird-fingerprints} are post-hoc on the archived confirmatory cells (18
builder$\times$seed cells, 384 admitted candidates, core-400 outcomes).
Both use the same record-combination rules, fixed tasks, and member
identity checks as the main reanalysis. They describe selection on
previously analyzed tasks.

\paragraph{Diversity-aware selection.} Each cell pools all admitted
candidates across arms. The reanalysis retains the legacy seed, 100
random database-half splits, 200 random subset draws per split and cell,
and candidate-selection rules. It records a new deterministic schedule:
the historical set-derived cell order was not archived, so identical
historical splits and draws cannot be recovered from the seed alone.
Selection uses development databases; evaluation uses the complementary
databases. The $1{,}800$ cell--split estimates share tasks across splits.
Methods are top-$k$ development accuracy, uniform random subsets, greedy
development oracle coverage, and greedy mean accuracy plus
$\lambda$ times oracle coverage for $\lambda\in\{0.25,0.5,1,2\}$.
All candidate choices are frozen within a split before its evaluation.

Table~\ref{tab:selection} retains the common AD single-call in every evaluated
subset; $k$ counts candidates only. Candidate-only values are recorded separately
to distinguish the historical estimand. Oracle and best-fixed use
held-out outcomes as descriptive upper bounds. Dev-fixed instead chooses
one member using development accuracy, with ascending member-name ties
and single-call first. Deterministic methods already retain a globally dev-best
candidate; differences in this comparator may arise from which tied
maxima survive, not improved maximum development accuracy.

\paragraph{Why the historical re-selection interval was discarded.}
A positive-weight re-selection percentile interval was considered for
the historical database-split comparison. It is not used for the
current uncertainty estimates. The following exact counterexample
explains why: the construction has no universal 95\% coverage guarantee. Let nine
independent databases each contain one Bernoulli($p$) task state. Sixteen
fixed candidates comprise eight state-0 specialists followed by eight
state-1 specialists; single-call is always wrong. Apply the canonical $k=8$
rules to four development and five held-out databases. With the recorded
tie rules, the expected div-only minus top-acc headroom statistic is
$(1-p^4)\,\mathbb{E}[\min(B,5-B)/5]>0$, where $B\sim\mathrm{Binomial}(5,p)$.
On the event that all nine states coincide, every positive reweighting
produces zero headroom for both methods, so the percentile interval is
$[0,0]$. Coverage is therefore at most $1-p^9-(1-p)^9$, or 61.26\% at
$p=0.1$. Averaging identical cells or overlapping fixed splits does not
remove this event. The failure is specific to that interval construction.

\subsection{Routing and exploratory selection}\label{sec:boundary}
The Phase-I leave-one-harness-out predictor yielded a $-3.4$\,pp
change against the best fixed harness in the tested DeepSeek population.
The Qwen estimate was $+0.9$\,pp (95\% CI $[-5.2,+6.9]$\,pp), and
task-held-out repair AUROC was $0.512$. These results show little
predictive separation in the tested populations. Table~\ref{tab:selection}
addresses a different question: how subset construction changes
held-out oracle coverage, fixed-member accuracy, and headroom.

\subsection{Archive diagnostics and common-set MATH rescoring}\label{app:archive-analysis}
The BIRD archive diagnostics concern 18 Phase-II cells. On BIRD, the integrity class (A) is REFUTED\_WITHIN\_SCOPE for every cell: the
combined observations contain overlapping acquisition records that
duplicate on the canonical key (resolved by the archived first-write-wins
policy, with recorded verdict-conflict counts), so the coverage numbers
below are computed on that deduplicated view. All cells show
single-shot coverage (B SUPPORTED). Stability, selectability, and
deployability are INSUFFICIENT\_EVIDENCE: these diagnostics use
single-run archive records. Per-record logical calls are read on
the same canonical deduplicated view as the rest of the reanalysis
($\RevisionLogicalCalls$ calls across $\RevisionCostRows$
candidate--task core-subset records, Table~\ref{tab:cost}).
Cost summaries therefore use recorded logical calls. For MATH, the current audit uses the same $36\times\RcvPairedN$
fully observed single-run matrix as the main text. Replaying the frozen
judge reproduces all $\RcvSingleCells$ scores, and the versioned
endpoint-sensitive judge produces identical scores on this subset.
Versioned artifacts preserve the earlier archive audit findings.
We retain the original scores for all main results. Older archive
selection policies and rescoring outputs remain in historical artifacts;
current policy results use the unchanged development-trained selector
and the common complete task set (Appendix~\ref{app:selection}).

\subsection{Quarantined MATH prompt-protocol pilot}
An earlier pilot mistakenly supplied a GSM8K-style description whose
numeric answer format did not match MATH-500. Code inspection found a
generate--verify harness that rejected nearly every answer and whose
fallback returned a stale loop variable or zero. These qualitative
failures illustrate a prompt-interface problem; the pilot's differently
scoped performance results are excluded from the current MATH tables.
