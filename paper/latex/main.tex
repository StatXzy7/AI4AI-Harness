\begin{abstract}
Automatically generated LLM harnesses can differ in source code and observed outcomes without offering stable task-specific advantages. We study how to separate program-dependent specialization from the benefits of repeated execution, reporting source-code, execution, and outcome diversity as three distinct quantities. In a BIRD text-to-SQL case study, trace inspection finds three execution-level routes through which apparently distinct harnesses fail to realize distinct strategies: claimed mechanisms absent from control flow (6 of 12 generated candidates), mechanisms present but never triggered (\react, 10/10), and broken multi-turn paths (1/12); code similarity has no rank association with outcome disagreement ($\rho=-0.01$; 21 of 66 generated pairs have identical correctness vectors despite all passing code-difference checks). A separate exploratory study on MATH-500 (35 generated harnesses, 400 tasks, one run each) shows 4.75\pp\ one-run oracle headroom over the best fixed member (which is the \bare{} harness itself). A fresh pre-registered collection then pairs eight generated harnesses against nine byte-identical \bare{} clone slots, with three independent repeats each: the repeat-averaged descriptive plugin is positive on both arms despite the clone population having zero specialization by construction ($2.54$\,pp on the real panel's $350$ complete tasks, $2.67$\,pp on the clone arm's $383$). The cross-fitted frozen-selection gain is $G_{\rm real}=0.17$\,pp (95\% CI $[-0.82,1.31]$) against $G_{\rm clone}=0.55$\,pp, so the clone-calibrated difference is $-0.10$\,pp (95\% CI $[-1.55,1.46]$, randomization $p=.7742$) on 342 paired complete tasks; the coverage gate fails (12.5\% of real-arm tasks excluded, above the frozen 10\% threshold), so the panel reports \textsc{Insufficient Evidence} --- neither a gain nor $1$\,pp equivalence. Together, these studies show that apparent oracle coverage gains in generated harness populations mix program specialization with the benefits of extra executions of one fixed stochastic program; harness-population evaluation should report one-run coverage opportunity, repeat-stable interaction, and pre-execution selection value as distinct quantities.
\end{abstract}

\subsection*{Ethics Statement}
All experiments use public BIRD and MATH-500 benchmark data and generated
program artifacts; no human participants, private records, or personally
identifiable information are collected.  Model calls are reported as part of
the experimental provenance, and the paper does not release credentials or
provider responses that would expose private data.  The main ethical risk is
overstating what one-run oracle gains imply for deployed routing; we therefore
report the unresolved selection and cost claims explicitly as
\textsc{Insufficient Evidence}.
