\begin{abstract}
When a population of LLM harnesses solves more tasks than its
best-performing individual member, does this gain reflect genuine
program specialization, or simply more opportunities to produce
correct answers? We investigate this question from two complementary
perspectives. On MATH-500, we compare generated harnesses with repeated
executions of byte-identical programs. Even when all nine execution
slots run the same single-call program, the repeat-averaged oracle
headroom reaches $\WpVthreeClonePlugin$ percentage points, showing that
positive coverage gains alone do not establish specialization among
programs. On BIRD, we further examine whether source-code differences
translate into distinct execution behavior. Trace analysis reveals
several failure modes: some claimed mechanisms are not implemented,
some are present but never triggered, and others execute but corrupt
the final output. Together, these findings provide a clearer evidence
framework for evaluating LLM harness populations: code-level
differences, actual execution behavior, stable task advantages, and
the ability to select and exploit those advantages should be tested
separately to more accurately assess the value of generated program
populations.
\end{abstract}

\subsection*{Ethics Statement}
All experiments use public BIRD and MATH-500 benchmark data and generated
program artifacts; no human participants, private records, or personally
identifiable information are collected.  Model calls are reported as part of
the experimental provenance, and the paper does not release credentials or
provider responses that would expose private data.  The main ethical risk is
overstating what one-run oracle gains imply for deployed routing; we therefore
report the unresolved selection and cost claims explicitly as
\textsc{Insufficient Evidence}.

\subsection*{Reproducibility Statement}
The manuscript specifies the populations, task splits, execution
conditions, scoring rules, statistical procedures, and sensitivity
analyses used for the reported results. The appendices provide
additional protocol details, calibration results, and worked examples.
Experimental code is not provided to reviewers; the methodological
and empirical claims are presented within the manuscript.
