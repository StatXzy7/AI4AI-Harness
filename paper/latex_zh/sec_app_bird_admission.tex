\section{BIRD 准入策略研究}\label{app:phase2-protocol}

本研究采用 $2{\times}2$ 析因设计加开放机制臂，包含六个构建器与三个种子。每槽至多 $R=3$ 次尝试，首次接纳即停止，不补足。两个开发数据库从评估池排除。评估集包含九个数据库的 $1{,}169$ 题与预抽取的 $400$ 题核心集；一次 $18$ 题流水线冒烟测试是已披露的开发隔离例外。官方 BIRD 评分器执行 $30$\,s 超时。响应缓存按模型身份区分，并采用跨进程锁；采集中发现并修正了缓存并发缺陷。

原主对比为配对构建器—种子单元上的 D$-$A，使用分层 bootstrap 与置换推断；共同核心上的析因次要分析采用 Holm 校正，并进行 K 匹配敏感性分析。仪器校准修正先于验证性结果。其他偏差包括操作性访问处理，以及对不一致观察的隔离。修正分析使用共享基线记录与数据库／题目重采样；这些修订发生在原分析规格之后。实际门控在结构上拒绝两种允许的提示层策略，各臂实际生成成本也不同。

\subsection{敏感性、重复审核与记录成本}
\paragraph{修正的 K 匹配与 R2 重放。}\label{app:r2}
两次重放都使用与修正主分析相同的确定性记录排序与共享数据库／库内题目抽取，在固定构建器内重采样种子（10{,}000 次重复）。K 匹配中，每个 A/B 与 C/D 对使用较小候选数；每个均匀候选子集被精确枚举一次。single-call 留在每个子集中，最佳固定在每次题目抽取的每个子集内部重算。这是规模敏感性分析，不是因果中介分解。保留全部 18 个单元（包括两个 A 子集为单成员的单元）使子集 D$-$A 从 \RevisionRtwoCached\ 变为 \RevisionRtwoOff\,\%（变化 \RevisionRtwoChange\,\%，95\% CI \RevisionRtwoChangeCI）。R2 子集提升空间排除 single-call，因为 R2 未获得匹配的 single-call 运行，故它不同于包含 single-call 的主估计目标；旧的 16 单元比较在此对账。这些是不稳定性测量，不是标准误，也不是平均处理效应的可检出下限；它们不证明每个对比都不变，也不识别 harness 间分歧中有多大部分是噪声。

R2 在 400 题上获得 70 个 harness，在可用时为每个 A/D 单元选择前两个可调用的已接纳候选。两组关缓存采集虽然重复标签相同，仍分别保留；程序身份与缓存运行核对。未获得匹配 single-call，因此 R2 提升空间在两种条件下都排除 single-call。修正分析保留单成员单元（其子集提升空间为零），得到全部 18 个配对单元。对缓存结果有 \RevisionRtwoFlips/28{,}000 次判定翻转（\RevisionRtwoFlipPercent\%），两次 D 关缓存轮次之间有 \RevisionRtwoRepeatFlips/14{,}400 次翻转（\RevisionRtwoRepeatPercent\%）。
仅为对账，限制到两臂都至少有两个成员的 16 个单元，缓存下 D$-$A 为 $\RevisionRtwoLegacyCached$\,\%、关缓存下为 $\RevisionRtwoLegacyOff$\,\%。这解释了与全单元估计的差别；两种分析都不识别未来执行方差、单独缓存的效应、或相对克隆的稳定互补优势。获取时间与缓存条件未被分离。

\paragraph{R3 仅 single-call 重复审核。}\label{app:r3}
R3 是一项单独的、更小的不稳定性审核：仅 \emph{single-call 基线}（无生成 harness）在相同 core-400 题、相同冻结目标（GLM-5.3-Flash，温度 0）上的三次独立关缓存执行。400 题中 58 题（14.5\%）在三次重复中至少一次改变 single-call 正确性；重复对之间的成对翻转率为 39/400、40/400、37/400（9.75\%、10.0\%、9.25\%）。把三次 single-call 重复当作三个伪成员（各一次执行）给出单次 oracle $72.25\%$，相对最佳单次重复准确率 $65.75\%$，即描述性的 $6.50$\,\% 同代码 oracle 缺口，由记录的官方评分结果计算。因此 R3 测量的是温度 0 API 非确定性下基线自身的观测不稳定率。这不是任何对比的标准误或效应大小下限，但它设定了重复控制成为解释必要项的尺度：没有它们，这个量级的 harness 对 single-call 差异不能归因于能力。

九个需审阅案例全部保留。第三个模型（\texttt{gpt-5.6-sol}）收到完整控制来源与轨迹，但没有作者参考标签或自动判定，用于对全部 32 个控制作来源—合同审查并对四类指定机制作语义裁决。
独立来源审查支持一个分解控制与两个错误分类控制符合，而仪器拒绝了它们。分解 stub 返回其文本在请求中出现的第一个计划步骤的载荷；因此在下一请求的上下文中保留较早步骤会再次取回较早载荷。分类检查移除了确切错误文本，但仍把普通 \texttt{Schema:} 标题计为一个类别，使提取的类别集与预期错误类不一致。这些是仪器在这些控制上的失败，不是目标模型的观测失败。
三个作者意图正控制被争议：两个模式链接控制保留了无关表，一个双视图控制批量处理其请求并错误处理空结果。其原始标签与审查分歧分别保留。在作者标签与来源审查一致的 29 个控制中，仪器拒绝了 13 个符合控制中的 3 个；全部 16 个不符合控制在指定语义审查后都被拒绝。因此仪器未通过这项有限控制检查。这些计数不估计生成种群中的错误率。
指定 16 个控制的语义裁决产生 7 个符合、8 个不符合、1 个不确定。不确定案例本就有结构失败，保留该失败而不解决其语义。这个小型、刻意平衡的控制集不是生成 harness 的随机样本。通过它并不能验证生产接口或取代准入政策的共同原始池比较。

\paragraph{修订仪器与新的独立控制集。}
Gate-v3 修正了分解请求归属，并把类别关键词与共享请求模板当作审阅线索而非自动拒绝。我们在新的模型上下文（\texttt{gpt-5.5} 编写、\texttt{gpt-5.6-sol} 审查）编写并审查新的 32 控制集之前固定此版本，仍为每机制两个意图正、两个意图负控制。审查包隐去作者标签、自动判定与仪器派生的归属元数据。全部 32 个控制接受来源审查；四个提示／表述组加分解中的 20 个控制还接受语义或数据流审查。结构结果为 8 通过、10 失败、14 需审阅，无执行失败。经一次记录在案的证据澄清，来源审查把 15 个控制分类为符合、17 个不符合；语义审查分类为 8 符合、11 不符合、1 不确定。

不确定的分类控制请求一个中间错误类别，但合成接口返回 SQL 文本。其回退随后选择了语义修复动作。这确立的是 fixture 中的响应类型不匹配，不是真实求解器的分类错误。第二个分类控制受到参考争议：其来源把提供的模式失败消息映射到语义动作。在 31 个无争议参考中，15 个符合控制有 14 个被接受、1 个仍未解决；全部 16 个不符合控制被拒绝。因此预先指定的有限检查因未决案例及错误分类缺乏足够一致的正覆盖而仍未满足。一个投票控制的符合性仅适用于结果仲裁；它未确立以任务为条件的候选生成。这些有限机制检查不验证完整 harness 运行，也不取代计划中的共同池政策比较。

\paragraph{运行时响应合同。}
我们随后测试了七个存档的无门控、策略强制候选，按固定顺序选择每种策略的首个可用候选，而非按表现；没有可用的格式守卫候选（附录~\ref{app:extraction}）。27 个合成场景同时暴露了候选与仪器的局限。双视图候选在第一个结果非空时跳过第二次执行，与其原本“两者都执行”的声明相反。相比之下，模式链接候选请求 JSON 却收到纯文本，分解请求中的完整计划使冻结探针无法唯一归属当前目标。
我们保留这些观察，并在另外 11 个开发场景中测试来源指派的响应配置。专用子问题字段识别了当前目标，可执行 SQL 载荷到达最终装配，内存 SQLite 数据库产生的四个错误引出相应的语法或模式修复指令。模式链接 JSON 改变了 SQL 编写请求中的显式表／列限制，但完整模式仍在场。因此仅凭保留模式上下文不能确立链接子集被忽略。这些暴露候选检查把响应接口失败与可观察的候选偏差区分开；它们不取代独立校准，也不提供修订后的基准结果。

\paragraph{统一接口与测量前参考审查。}
Gate-v4 把来源指派的响应接口与五个未变的 Gate-v3 机制探针结合。另写的 32 控制集（\texttt{gpt-5.6-sol}）在执行前接受盲测来源审查。作者熟悉更早的控制失败；此来源审查中发现的模式响应与声明投票参数不匹配在保留初版的同时被修正。修订参考在每机制有两个一致符合与两个一致不符合控制。冻结其来源、配置与依赖后，一次测量覆盖 124 个场景，无执行异常。结构结果为 4 通过、6 失败、22 需审阅。

一个新的审查上下文（\texttt{gpt-5.5}）收到全部来源与实际轨迹，但没有参考标签、来源审查决定或自动判定。其首次判定为 18 符合、14 不符合。在预先指定的混合规则中保留结构失败会接受全部 16 个符合参考，但也接受一个不符合的提示控制，故有限零错误标准未满足。该控制正确重述已有提示，却在未提供提示时虚构了强制排序。一次记录在案的、有针对性的证据澄清纠正了这一疏漏，也纠正了一个把同一请求的两个样本当作独立表述的双视图判定。后一控制本已被结构拒绝。澄清后的判定与全部 32 个参考一致，但这次跟进不取代首次盲测结果，也不构成新的独立校准通过。此检查中未执行任何仪器重跑、提供方生成或基准评估。

\paragraph{声明词表的范围。}
这些控制覆盖八个策略强制合同，不覆盖自由臂的四种声明（repair、vote、twostage、plain）。在原自由提示中，vote 指定多次采样与选择但未指定三票多数投票；twostage 指定产物消费但无特定响应接口。plain 声明还指定无控制流机制，而自由提示要求控制流变更。因此把八策略门控应用于这些声明需要另行固定语义规则与不确定政策，而不是静默把 vote 当作 vote3 或在观察其结果后选择兼容配置。这一来源级范围缺口不估计生成候选的错误拒绝率。
