\section{BIRD 准入策略研究}\label{app:phase2-protocol}

确认性研究采用包含六个构建器与三个种子的 $2{\times}2$ 析因设计；开放机制臂 II-E 仅用于开发。每槽至多 $R=3$ 次尝试，首次接纳即停止，不补足。两个开发数据库从评估池排除。评估集包含九个数据库的 $1{,}169$ 题与预抽取的 $400$ 题核心集；一次 $18$ 题流水线冒烟测试是已披露的开发隔离例外。官方 BIRD 评分器执行 $30$\,s 超时。响应缓存按模型身份区分，并采用跨进程锁；采集中发现并修正了缓存并发缺陷。

原主对比为配对构建器—种子单元上的 D$-$A，使用分层 bootstrap 与置换推断；共同核心上的析因次要分析采用 Holm 校正，并进行 K 匹配敏感性分析。仪器校准修正先于验证性结果。其他偏差包括操作性访问处理，以及对不一致观察的隔离。修正分析使用共享基线记录与数据库／题目重采样；这些修订发生在原分析规格之后。重叠采集记录按规范身份去重，采用记录在案的先写先得规则；判定冲突保留在来源审核中，当前表格使用该去重视图。实际门控可能在结构上拒绝已通过中性有效性检查的纯提示变换，各臂实际生成成本也不同。

\subsection{敏感性、重复审核与记录成本}
\paragraph{修正的 K 匹配与 R2 重放。}\label{app:r2}
两次重放都使用与修正主分析相同的确定性记录排序与共享数据库／库内题目抽取，在固定构建器内重采样种子（10{,}000 次重复）。K 匹配中，每个 A/B 与 C/D 对使用较小候选数；每个均匀候选子集被精确枚举一次。single-call 留在每个子集中，最佳固定在每次题目抽取的每个子集内部重算。这是规模敏感性分析，不是因果中介分解。保留全部 18 个单元（包括两个 A 子集为单成员的单元）使子集 D$-$A 从 \RevisionRtwoCached\ 变为 \RevisionRtwoOff\,pp（变化 \RevisionRtwoChange\,pp，95\% CI \RevisionRtwoChangeCI）。R2 子集提升空间排除 single-call，因为 R2 未获得匹配的 single-call 运行，故它不同于包含 single-call 的主估计目标；全部 $18$ 个单元均保留。这些是不稳定性测量，不是标准误，也不是平均处理效应的可检出下限；它们不证明每个对比都不变，也不识别 harness 间分歧中有多大部分是噪声。

R2 在 400 题上获得 70 个 harness，在可用时为每个 A/D 单元选择前两个可调用的已接纳候选。两组关缓存采集虽然重复标签相同，仍分别保留；程序身份与缓存运行核对。未获得匹配 single-call，因此 R2 提升空间在两种条件下都排除 single-call。修正分析保留单成员单元（其子集提升空间为零），得到全部 18 个配对单元。对缓存结果有 \RevisionRtwoFlips/28{,}000 次判定翻转（\RevisionRtwoFlipPercent\%），两次 D 关缓存轮次之间有 \RevisionRtwoRepeatFlips/14{,}400 次翻转（\RevisionRtwoRepeatPercent\%）。
这些观测重放不识别未来执行方差、单独缓存的效应或相对克隆的稳定互补性。获取时间与缓存条件未被分离。

\paragraph{R3 仅 single-call 重复审核。}\label{app:r3}
R3 是一项单独的、更小的不稳定性审核：仅 \emph{single-call 基线}（无生成 harness）在相同 core-400 题、相同冻结目标（GLM-5.3-Flash，温度 0）上的三次独立关缓存执行。400 题中 58 题（14.5\%）在三次重复中至少一次改变 single-call 正确性；重复对之间的成对翻转率为 39/400、40/400、37/400（9.75\%、10.0\%、9.25\%）。把三次 single-call 重复当作三个伪成员（各一次执行）给出单次 oracle $72.25\%$，相对最佳单次重复准确率 $65.75\%$，即描述性的 $6.50$\,pp 同代码 oracle 缺口，由记录的官方评分结果计算。因此 R3 测量的是温度 0 API 非确定性下基线自身的观测不稳定率。这不是任何对比的标准误或效应大小下限，但它设定了重复控制成为解释必要项的尺度：没有它们，这个量级的 harness 对 single-call 差异不能归因于能力。

\subsection{准入范围与工具局限}
\label{app:free-vocabulary}
自由臂中，构建器从 repair、vote、twostage 和 plain 四类声明中选择。vote 要求多个样本与选择，不一定是三路多数投票；twostage 要求消费产物，但不指定响应接口。plain 不声明控制流机制，尽管提示要求改变控制流。因此，“自由”指在指定词汇内由构建器选择，而非不受约束的接口。

门控同时包含结构筛选与符合性验证。独立开发检验发现误拒、请求归属和响应接口缺陷，以及未决的符合性判断。后续接口修订与裁决没有产生修订后的基准结果。因此，所报告处理仍是实际实现的组合筛选政策；这些开发检验不确立准入工具的一般语义有效性。

\paragraph{生成接口局限。}\label{app:extraction}
$36$ 个强制臂单元的全部 $108$ 次格式守卫尝试均未通过中性有效性检查：$71$ 条日志报告字符串未终止，$36$ 条报告没有 Python 围栏，一条报告提供方超时。合成示例复现了存档非贪婪代码围栏提取器的截断行为，但完整构建器消息与各历史尝试实际执行的确切版本未被保留。这些观察记录上游有效性失败，不证明预期机制不符合声明，也不把每次拒绝都归因于门控。
