\section{BIRD 执行轨迹与补充分析}\label{app:bird-traces}
Phase I 对应 BIRD 发现研究，Phase II 对应准入研究。本附录展开前者的程序与执行路径。
\subsection{发现研究的程序群体与条件}\label{app:phase1-provenance}

\paragraph{程序群体与评分。}
发现研究在 $60$ 题上评估 GLM-5.3-Flash 经 TTHE 提议者生成的十二个候选，以及 \bare{} 和 \react{}（\S\ref{sec:f1-collapse}）。准入检查导入与冒烟执行。基线在两次发现运行间翻转 $60$ 题中的三题。在两个保留 SQL 的矩阵上，行集合代理评分器与官方 BIRD 评分器一致率为 0.97--0.99，没有代理判对而官方判错的案例。

\paragraph{开发暴露。}
人工控制在查看轨迹后设计，$24/151$ 个评估项与协议开发重叠，其余量作描述性报告。早期记录缺少生成工具与逐尝试日志，无法重建等生成预算。

\subsection{发现研究的结果与人工控制}\label{app:bird-discovery}

全部候选通过代码差异检查，但 $21/66$ 个生成对的正确性向量相同（含基线为 $36/91$）。$91$ 对上的源码相似度与正确性分歧相关为 $\rho=-0.010$（图~\ref{fig:phenomenon}）。这 $60$ 题的平均分歧为 $3.3\%$，仅生成候选为 $3.8\%$，联合修复率为 $7.7\%$，单次余量为 $3.3$\,pp。轨迹展示不同程序产生相近结果的具体路径。

\subsection{轨迹区分机制缺失、未触发与执行失败}
\textbf{T1：描述存在，实现缺失。}十二个候选中六个声称检索或自检，却只有一次模型调用，未实现所描述的检索或自检步骤。
\textbf{T2：机制存在，未被触发。}全部十个被审 \react{} 任务的首个 SQL 均无错误执行，修复分支未启动，最终 SQL 与 \bare{} 相同；执行成功仍可伴随语义错误。
\textbf{T3：执行发生，输出损坏。}十二个候选中一个执行多轮修复，却将自然语言作为 SQL 返回，丢掉基线答对的题。

三个案例分别定位实现、分支触发与输出有效性。四个人工编写、路径不同的控制在 $60$ 题上产生 $6.67$\,pp 余量，在 $151$ 题上为 $7.28$\,pp。这些轨迹检查后的控制缺少匹配重复与克隆；$24/151$ 的开发重叠见附录~\ref{app:phase1-provenance}，具体轨迹见附录~\ref{app:examples}。

\subsection{轨迹审核的完整样例}\label{app:examples}

T1 的六／十二计数覆盖完整发现群体。独立轨迹审核在十道题上跟踪五个 harness：\bare{} 基线、\react{}、生成的单次调用候选、超时重试候选及多轮修复候选（5 $\times$ 10）。下文以一题展示路径。日志中的 SQL 摘录上限为 120 字符，截断标为 \emph{[trunc.]}。

\paragraph{任务。}BIRD 开发集问题 352（\texttt{card\_games} 数据库；题目文本逐字，拼写错误为数据集原有）：
\begin{quote}\small\ttfamily
Calculate the percentage of the cards availabe in Chinese Simplified.
\end{quote}
其 BIRD 提示：
\begin{quote}\small\ttfamily
'Chinese Simplified' is the language; percentage = Divide(Sum(id where
language = 'Chinese Simplified'), Count(id)) *100
\end{quote}
标准 SQL：
\begin{quote}\small\ttfamily
SELECT CAST(SUM(CASE WHEN T2.language = 'Chinese Simplified' THEN 1 ELSE 0
END) AS REAL) * 100 / COUNT(T1.id) FROM cards AS T1 INNER JOIN foreign\_data
AS T2 ON T1.uuid = T2.uuid
\end{quote}
\bare{} harness 回答：
\begin{quote}\small\ttfamily
SELECT SUM(CASE WHEN language = 'Chinese Simplified' THEN 1 ELSE 0 END) *
100.0 / COUNT(id) AS percentage FROM foreign\_data;
\end{quote}
在发布数据库上，标准查询得到 8.7734，基线查询得到 8.7728。官方评分器将基线查询判错：它直接在 \texttt{foreign\_data} 上计数，而标准查询在连接 \texttt{cards} 之后计数；提示没有写明该连接。

\paragraph{\react{}（T2：修复未触发）。}
首个提示与 \bare{} 逐字节相同。SQL 执行成功，因此数据库错误重试未触发。全部 10 道被审题沿此路径运行：执行 SQL，但 10/10 最终查询与 \bare{} 逐字节相同。

\paragraph{单次调用候选（T1：修复缺失）。}
文档字符串的“保守修复”要求输出 token 上限与仅答案块，实际仅调用一次模型再提取 SQL。上限只是环境默认值（2{,}048，对比运行时 32{,}000），没有 harness 控制流实现，也未在短答案上生效。样例题用一次调用、零次 SQL 执行返回同一错误的 \texttt{foreign\_data} 查询，仅空白不同。全部 10 题的 SQL 执行数均为零，6 个最终查询与 \bare{} 逐字节相同，其余差异来自提示改写，未实现检索、自检或修复。

\paragraph{超时重试候选（看门狗未触发）。}
守护线程看门狗包裹 coder 调用，停滞超过 40\,s 时发出一次对冲重复请求。审核中未出现停滞：SQL 执行数为零，全部 10 题的最终 SQL 与 \bare{} 相同。

\paragraph{多轮修复候选（T3：多轮路径执行失败）。}唯一一个实现了真正执行—检查—修复的被审候选把模型的\emph{自然语言说明}当作最终 SQL 返回。在一道 \bare{} 答对的题（“State the alternative languages available for card named Annul numbered 29.”）上，其记录的最终 SQL 逐字开头为：
\begin{quote}\small\ttfamily
with "only a single read-only SELECT is allowed". The previous "query" was
actually just prose text (the model wrote rea\emph{[trunc.]})
\end{quote}
该修复提示下，输出契约再次失败：被要求修复一个“实际上只是自然语言说明”的查询时，冻结目标继续返回自然语言推理；由于找不到 SQL 块，推理文本便被当作查询提交。该题从基线正确翻转为 harness 错误。
