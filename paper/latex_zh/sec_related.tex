\subsection{面向 LLM 的 harness 生成}\label{related:generation}
一系列工作为冻结模型生成任务专用的外围程序。TTHE 通过 LLM 提议者／评判者循环演化文本转 SQL harness \citep{tthe2026}；Self-Harness 展示模型改进自身 harness 的能力 \citep{selfharness2026}；JIT-Agent 训练模型在推理时为每道任务生成 harness \citep{jitagent2026}；Task-CoEvolve 联合演化任务与程序框架 \citep{coevolve2026}。2026 年的同期研究从验证侧将行为信号纳入演化：HarnessLens 在演化过程中以行为检查分配 rollout 预算 \citep{harnesslens2026}；HarnessFix 根据轨迹诊断修复 harness \citep{harnessfix2026}；AHE 按每次编辑自述的行为预测进行验证 \citep{ahe2026}；带门控的语义质量—多样性搜索按 LLM 指派的问题描述符演化种群 \citep{gatedqd2026}；Harness Handbook 研究行为定位与外层搜索 \citep{handbook2026}。

我们的分析单位与问题有所不同。表~\ref{tab:nearest} 比较最接近的两个系统。HarnessLens 将行为作为演化循环内部的计算分配信号；我们将整个种群的行为多样性作为结果性质，比较其在生成侧干预下的变化。HarnessBank \citep{gatedqd2026} 记录搜索空间坍缩，并以门控筛选维护语义多样性库；我们的一致性门控不进行语义评分，而是借助反事实轨迹探针机械检查声明机制是否执行，再通过析因对比比较准入策略。但实际门控也排除了允许的提示变换，因此当前实验无法单独识别验证的因果贡献。

\subsection{Harness 的条件效用与路由}\label{related:routing}
Harness 质量取决于具体实例：\citet{nouniversal2026} 和 \citet{nonmonotone2026} 指出，单个 harness 不会在所有实例上占优。HELIX 评估同源 harness 的完整结果矩阵及超过最佳固定候选的组合互补性，并将路由器列为未来工作 \citep{helix2026}。STS 在六种固定人工程序框架之间路由 \citep{sts2026}；GRASP 在开发阶段将技能编辑经门控纳入库中 \citep{grasp2026}；\citet{cfrouting2026} 在“不搜索、搜索、弃答”之间学习实例级路由；\citet{agenticrouting2026} 在 harness 内部路由模型。经典算法选择 \citep{rice1976} 及 SATzilla 等组合求解器 \citep{xu2008satzilla,kotthoff2016} 根据实例特征选择列举的算法。

我们的候选是完整的自动生成 harness；本研究测量选择器将继承的种群结果结构（\S\ref{sec:boundary}），而不构建选择器。我们诊断执行路径，并通过包含结构筛选成分的析因处理比较生成策略；当前研究尚未确立稳定的可选择价值。
\subsection{LLM 种群的行为多样性}\label{related:diversity}
LLM 输出多样性主要在样本层面（自洽性、多样化解码）或智能体策略层面得到研究。语法不同的程序可能表现相同，这与程序合成和变异测试中的覆盖缺口相呼应；本研究将其具体化为 AI 生成 harness 种群的测量，并给出机制层面的分类。
