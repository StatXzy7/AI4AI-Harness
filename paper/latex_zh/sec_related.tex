\paragraph{自动化智能体与 harness 设计。}
可执行程序为调整 LLM 行为提供了灵活空间。ADAS 直接搜索这一空间 \citep{adas2024}；Self-Harness 利用失败轨迹提出修改，经回归测试后保留修改 \citep{selfharness2026}；TTHE 在评估期间依据无标签轨迹调整 harness \citep{tthe2026}。相关系统改进任务适配与验证资源分配 \citep{jitagent2026,coevolve2026}，或通过验证、诊断、定位和策略演化呈现 harness 行为 \citep{harnesslens2026,harnessfix2026,ahe2026,gatedqd2026,handbook2026,harnessforge2026}。\citet{metaagents2025} 报告，所研究的自动设计智能体在逐题评分模式上的多样性较低。本文从执行轨迹和重复结果两个角度观察程序群体：轨迹揭示实际执行的机制，同代码重复衡量采样带来的覆盖。这一视角将程序等价与变异测试 \citep{budd1982,papadakis2019} 连接到生成 harness 群体的性能归因。

\paragraph{重复采样与集成。}
即使程序固定，多次执行也能提高答案覆盖。Pass@$k$ 衡量 $k$ 次采样中至少一次成功的概率；自一致性与相同智能体的集成聚合多次尝试 \citep{chen2021codex,selfconsistency2022,moreagents2024}，名义温度为 $0$ 的调用也可能变化 \citep{nondeterminism2023}。这些收益构成本文执行预算匹配比较中的采样参照。另一个区别是选择发生在何时。执行后的验证器对候选解排序 \citep{llmverifier2026}；集成选择在验证集上选定模型组合，在推理时平均预测 \citep{caruana2004}。本文的冻结选择器在执行前选择程序，oracle 重放则衡量记录输出中的覆盖。

\paragraph{选择与资源配置。}
将程序群体转化为有用的选择，使 harness 设计与算法选择及组合求解相联系 \citep{rice1976,xu2008satzilla,kotthoff2016}。HELIX 利用群体内互补的轨迹扩展经验证的覆盖，并为模型改进提供数据 \citep{helix2026}。STS 比较六种推理范式，训练基于嵌入的路由器，实现部分 oracle 收益 \citep{sts2026}。模型--问题组合间 \citep{nouniversal2026} 及所评估模型间 \citep{nonmonotone2026} 的 harness 敏感性、搜索路由 \citep{cfrouting2026} 和基于偏好训练的模型路由 \citep{routellm2024}，进一步说明按任务选择的意义。GRASP 在新增错误约束下选择对有界技能库的编辑 \citep{grasp2026}。本文固定目标模型，在同一程序群体中测量 oracle 覆盖、跨重复稳定的逐题优势与实际选择收益。定量交互与定性交互的区别 \citep{gailsimon1985} 则说明，效应大小可以变化，而最佳动作仍然相同。
