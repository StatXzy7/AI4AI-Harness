\paragraph{对评估的启示。}
本文区分了三种容易被当作同类证据的观察：相同程序产生正的 oracle 余量；生成程序产生可重复的评分模式；冻结选择器却没有获得收益，完整预算下 oracle 覆盖也持平。因此，有用专长的主张需要将可重复的\emph{优势}、任务交叉与可用选择规则连接起来，生成面板的持续损失涉及 $\RcvLossTasks$ 道题，持续获胜仅出现在一道题上：可重复结构主要刻画程序在哪里失分，而非选择器在哪里获益。若将优势归因于某种机制，则轨迹需要说明实际执行了什么，干预需要检验其贡献。

\paragraph{局限。}
受控 MATH 面板是在一个求解模型、已评估任务上抽取的低调用程序。修订的留出重复过程和新增可重复性分析均在采集后形成。初始研究按其停止规则结束；另行记录的补采集阶段发生在查看早期结果之后，并保持程序、任务、求解器和重复次数不变。$\RcvPairedN$ 题分析集按完整性筛选，集内观测完整。被排除的 $\RcvExcludedN$ 道题观测难度更高、基线准确率更低（附录~\ref{app:wp1r}），因此性能估计描述所选题集。三次重复的诊断功效较低，稳定评分模式还可能包含固定评分器的格式效应。校准结果保持 \textsc{Insufficient Evidence}（证据不足）。零路由收益对应所测选择器与特征。重放统一 harness 执行次数，模型调用数和 token 成本随程序而异。BIRD 发现适用于其自身的评分与采集条件。
