\paragraph{额外覆盖能说明什么。}
本文将程序群体中常被期待同时出现的三种性质区分开来：找到更多正确答案、在重复执行中保持任务优势，以及将这些优势用于选择。同代码对照使这一区分具体可见。逐字节相同的程序即使经过重复平均，也能产生正的 oracle 余量，而其稳定互补性按构造为零。因此，额外覆盖确实代表一种采样机会，但将它归因于程序专长还需要进一步证据。这一对照改变了对程序群体成功的解释：评价时必须同时考虑固定程序的重复执行已经能够提供什么。

\paragraph{可重复性需要结合优势的方向来理解。}
生成面板揭示了第二层区别。较强的评分模式残差相关性表明，程序身份与持续差异相关，但这些差异主要定位了生成程序在哪些题上输给基线。这与式~\ref{eq:identity} 中的交叉优势条件一致：劣势大小的变化可以高度可重复，却不改变应该选择哪个程序。因此，关于专长的论断既需要回答谁在哪些任务上获胜，也需要检验这些胜利能否重现。在所测面板中，持续失分与持续获胜之间的不对称，解释了为什么可重复结构很少为偏离基线提供观测支持。冻结分类器在每道题上都直接选择 \bare{}，与这一模式一致；其零收益并不构成所有可能选择器的性能上限。

\paragraph{围绕任务需求设计机制。}
BIRD 轨迹从执行层面补充了上述统计区分。一个宣称的操作必须被实现、在相关输入上触发，并产生有效答案，才可能对性能作出贡献。未触发的修复分支尤其具有启发性：SQL 可以成功执行，却回答了错误的问题，因此仅由执行错误触发的修复可能恰好遗漏这类失败。这提示我们，应当将机制与需要触发它的任务条件一起设计。一个有针对性的后续实验，是在能够触发目标分支的任务上，对同一程序比较机制开启与关闭，再检验可能出现的优势能否在新的执行中保持。这样的干预能够考察机制的因果贡献；当前轨迹则定位了这条路径上的失败环节。

\paragraph{如何评价扩大程序群体的价值。}
这些发现提示，评价应围绕程序群体意在改善的决策展开。对于执行前路由，目标是能够从答案揭晓之前可得的信息中预测的任务优势。对于同时执行多个程序的组合，目标是可实际部署的答案选择或聚合方法所带来的收益。本文的 oracle 重放衡量可获得的答案，尚未解决后一种决策。完整预算下的覆盖持平，说明固定程序的额外执行应当成为必要的比较对象。后续研究应结合这一对照，根据对任务交叉优势的检测能力确定重复次数，并在匹配模型调用或 token 预算的条件下进行比较。由此才能检验，增加程序是否在创造更多采样机会之外，进一步提高了推理的价值。

\paragraph{适用范围与未决问题。}
MATH 证据来自选定的低调用程序面板、一个求解器和三次重复。重复诊断与共同完整题集重分析在采集后形成；补采集保持程序、任务、求解器和重复次数不变。排除的 $\RcvExcludedN$ 道题比纳入的 $\RcvPairedN$ 道题更难（附录~\ref{app:wp1r}），记录的评分模式也包含答案格式效应。校准显示三次重复的检验功效较低，稳定互补性仍未判清：\textsc{Insufficient Evidence} 不意味着等价。选择结果对应冻结策略；重放匹配 harness 执行次数，模型调用与 token 随程序变化。BIRD 使用独立的程序群体与评分条件，因此其轨迹提供执行层面的补充证据，尚不能作为 MATH 结果的因果解释。更广泛的求解器与程序群体仍有待检验。
