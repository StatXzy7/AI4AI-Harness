\subsection{BIRD 轨迹定位代码到执行之间的中断}\label{sec:supporting}\label{sec:f1-collapse}
源码差异可能在产生有效最终答案之前消失。补充的 BIRD 研究在独立程序群体上，使用任务对应的评分与执行协议，直接追踪这一过程。这里的机制指已实现的提示变换、工具使用或控制流操作。对实际程序行为的检查，从执行层面补充了 MATH 对照。

\paragraph{不同源码常产生相同的评分结果。}
全部 $12$ 个发现候选都通过代码差异检查，但 $21/66$ 个生成候选对的正确性向量相同，计入基线时为 $36/91$。源码相似度与正确性分歧几乎没有秩相关（$\rho=-0.010$）。这些 $60$ 题上的一致促使我们检查轨迹（附录图~\ref{fig:phenomenon}）。

\paragraph{轨迹区分未实现、未触发和输出失败的机制。}
\textbf{T1：描述了但没有实现。}$12$ 个候选中的 $6$ 个描述了检索或自检，实际只有一次模型调用，未实现所描述的检索或自检步骤。这一分类覆盖全部十二个候选，五个 harness 的轨迹审核提供具体样例。

\textbf{T2：存在但未触发。}全部 $10$ 道已审 \react{} 任务的第一次 SQL 均执行成功，修复分支从未触发，最终 SQL 与 \bare{} 相同。因此，执行成功仍可能让语义错误的答案保持不变。

\textbf{T3：执行了但输出失败。}一个候选执行多轮修复，却把自然语言说明作为最终 SQL，丢失了基线答对的任务。三类情况分别定位实现、分支触发和有效输出的检查。附录~\ref{app:bird-traces} 提供具体轨迹与人工控制，并说明其开发暴露限制。

独立的 BIRD 准入研究发现，强制策略加门控相对自由无门控的平均余量差为 $\RevisionPrimaryDelta$\,pp。该门控同时包含结构排除与合规验证（附录~\ref{app:phase2-protocol}）。这些 BIRD 观测具体展现了程序执行的路径：源码层面的差异需要被实现、被触发，并最终产生有效答案。可重复的任务优势与选择价值则衡量这些执行随后带来的收益。
