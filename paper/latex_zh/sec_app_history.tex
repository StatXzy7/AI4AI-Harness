\subsection{早期生成协议探查及其局限}\label{sec:phase1probes}
Phase I 还探查了生成侧修复——策略强制自由形式协议（指派机制，导入／冒烟准入）与编译式 Harness IR。在策略强制协议下，三个构建器中有两个产生的种群点估计超过预先指定阈值（Qwen3.8-Flash 5.96、DeepSeek-V4-Flash-Vision-Exp 7.95\,\%；旧协议臂为 4.64\,\% 未达标），且逐策略接纳随构建器身份排序（在有日志工具下 GLM-5.3-Flash 3/8、Qwen3.8-Flash 7/8、DeepSeek-V4-Flash-Vision-Exp 8/8）。这些观察为 Phase II 提供动机，但不是验证性的，原因有三并已披露：设计是两个嵌套对比，无法把协议主效应与构建器主效应分开；早期运行缺少逐尝试日志，预算相等无法审核；准入是导入／冒烟检查，不是 \S\ref{sec:f2-admission} 的反事实一致性门控。完整条件见附录~\ref{app:phase1-provenance}。

\paragraph{生成空结果失败（M0）。}用 Qwen3.8-Flash 与 DeepSeek-V4-Flash-Vision-Exp 构建器重跑原优化循环，产生 40 个与 \bare{} 基线源码逐字节相同的候选。代码同一并不意味着随机执行也相同。这次运行没有提供不同代码的种群；它作为另一种更原始的失败模式报告——流水线根本没有产生不同种群。上述坍缩主张完全基于来源确实不同的发现阶段种群。

\paragraph{生成来源缺口。}早期自由形式种群在会话中产出；其生成工具未保存，也不存在逐尝试日志——因此这些运行的预算相等无法审核，我们也不作此主张。它们的准入是评估时的导入／冒烟检查，\emph{不是} Phase-II 的反事实一致性门控。后续生成过程记录每次尝试（3 次重试、16{,}384 token 预算、逐尝试阶段与结束原因）；完整的逐策略网格与构建器接纳排序（3/8、7/8、8/8）来自该有日志工具，相对冻结的准入决定属于事后。

\subsection{上游代码提取审计}\label{app:extraction}
在 36 个强制 C/D 单元中，全部 108 次 \texttt{format\_guard} 尝试均未通过中性有效性：71 条日志报告 Python 字符串未终止，36 条报告无 Python 围栏，1 条报告提供方超时。存档生成器的非贪婪 Python 围栏提取器在随后第一个三反引号处终止，包括 Python 字符串内部的三反引号。三个合成的、语法有效、在普通字符串、文档字符串或正则中包含 SQL 围栏的程序变成了无效前缀；而提取器仍把其截断标志设为 false。审核的提取器与保留实现一致，但历史尝试记录无法验证当时实际执行的版本。完整构建器消息未被该生成器保存。因此失败模式与提取损坏相容，但不证明所有历史失败都由此造成，也不证明修复后的候选会通过准入。我们找到 74 个保留的提取程序，全部语法无效；其中三个与无围栏日志并存，作为来源冲突保留，不归属于那些尝试。这些发现把一个生成接口失败置于门控显式策略排除之旁。

\subsection{审后提供方获取状态}
审后的提供方获取尝试未形成完整共同池：传输中断把已完成响应、未闭合请求与未启动尝试留在不同的可审计状态中。这些记录为来源与缺失性核算保留，但被排除于关于种群表现、成本或稳定互补性的主张之外。因此，稿件不把提供方可用性或部分获取用作未解决的克隆控制问题的证据。


\subsection{历史 BIRD 选择分析}\label{app:rich}
选择分析与附录~\ref{app:bird-fingerprints} 的指纹分析都是对存档验证性单元（18 个构建器$\times$种子单元、384 个接纳候选、core-400 结果）的事后分析。两者使用与主重分析相同的记录合并规则、固定任务与成员身份检查。它们仍是描述性的：这些题目此前已被分析过，这不是独立迁移验证。

\paragraph{多样性感知选择。}每个单元合并跨臂的全部接纳候选。重分析保留旧种子、100 次随机数据库对半划分、每划分每单元 200 次随机子集抽取及候选选择规则。它记录一个新的确定性调度：历史的集合派生单元顺序未存档，因此仅凭种子无法恢复相同的历史划分与抽取。选择使用开发数据库；评估使用互补数据库。重叠划分不是 1{,}800 个独立实验。方法为开发准确率 top-$k$、均匀随机子集、贪心开发 oracle 覆盖、以及贪心平均准确率加 $\lambda$ 倍 oracle 覆盖（$\lambda\in\{0.25,0.5,1,2\}$）。所有候选选择都在划分的评估之前于划分内冻结。

表~\ref{tab:selection} 在每个被评估子集中保留共同的 AD single-call；$k$ 只计候选。仅候选估计与包含基线的估计分开记录，以区分历史估计目标。Oracle 与最佳固定使用留出结果作为描述性上界。开发固定改为用开发准确率选一个成员，成员名并列时升序、single-call 优先。确定性方法本就保留一个全局开发最佳候选；该比较器的差异可能来自哪些并列最大值存活，而非开发最大准确率提高。

\paragraph{重选择不确立区间覆盖。}
一个精确反例排除了我们提出的正权重重选择百分位区间的普遍 95\% 覆盖保证。令九个独立数据库各含一个 Bernoulli($p$) 任务状态。16 个固定候选由八个状态 0 专家后接八个状态 1 专家组成；single-call 恒错。把 canonical $k=8$ 规则应用于四个开发库与五个留出库。在记录的并列规则下，仅多样性减 top-acc 提升空间统计量的期望为 $(1-p^4)\,\mathbb{E}[\min(B,5-B)/5]>0$，其中 $B\sim\mathrm{Binomial}(5,p)$。在全部九个状态恰好相同的事件上，每种正加权都给两种方法产生零提升空间，故百分位区间为 $[0,0]$。因此覆盖率至多为 $1-p^9-(1-p)^9$，在 $p=0.1$ 时为 61.26\%。对相同单元或重叠固定划分取平均不能移除该事件。此界限针对所述构造与区间，不涉及 BIRD 特定覆盖率，也不涉及其他推断方法的不可能性。

\subsection{路由与探索性选择}\label{sec:boundary}
Phase-I 留一 harness 预测器未在所测 DeepSeek 种群中超过最佳固定 harness（$-3.4$\,\%）；Qwen 估计为 $+0.9$\,\%（CI $[-5.2,+6.9]$），题目留出的修复 AUROC 为 0.512。这些预测器与划分特定结果不确立价值预测。canonical W1 分析同样是描述性的：在 $k=8$ 时，多样性相对 top-准确率选择使 oracle 变化 $\RevisionWoneOracle$\,\%、最佳固定变化 $\RevisionWoneBest$\,\%、提升空间变化 $\RevisionWoneHeadroom$\,\%；开发选定固定成员变化 $\RevisionWoneFixed$\,\%。没有一个是经验证的路由增益（附录~\ref{app:rich}）。

\subsection{历史档案诊断与重评分}\label{app:archive-analysis}应用于 MATH-500 存档（36 成员 $\times$ 400 题）与 18 单元 BIRD Phase-II 存档。在 BIRD 上，完整性类（A）对每个单元为 REFUTED\_WITHIN\_SCOPE：冻结输入清单包含重叠的采集记录，其行在 canonical 键上重复（由存档的先写先得策略解决，并记录判定冲突计数），因此下述覆盖数字在该去重视图上计算，而非在无冲突存档上；评分器重放在此路径上不执行，被报告为未运行而非通过。在此范围内，所有单元显示单次覆盖（B SUPPORTED）；稳定性、可选择性与可部署性按冻结规则为 INSUFFICIENT\_EVIDENCE，因为存档不含匹配重复也没有供政策训练的开发／评估划分——不是因为成本缺失：逐记录逻辑调用已存档，并在与其余重分析相同的规范化去重视图上读取（$\RevisionCostRows$ 条候选–题核心子集记录上共 $\RevisionLogicalCalls$ 次调用，表~\ref{tab:cost}），但 token／美元成本仍不可恢复。在 MATH 上，冻结选择政策在 400 道评估题的前 80 道上训练（这 80 道从所有 D/E 命题中留出；存档不含开发集执行：附录~\ref{app:crossdomain} 的 100 题开发划分仅用于生成冒烟测试，故政策划分从评估侧切出，留下 320 道计分题），在每道评估题上与开发固定（single-call）持平，因此可选择性与可部署性为 INSUFFICIENT\_EVIDENCE 而非被否证。三个已发表数字被修正（结果向量计数的成员口径，现为计入 single-call 的 33/36 成员与 32/35 生成 harness；生成 harness 准确率范围 0.6825--0.915，此前印为 0.68--0.87；最佳固定 = single-call 的提升空间分解明确写出），两个过载的指标名被消歧（并集全败对任一候选失败），一个保留判定控制在显式定义下确认了报告的一对数字（联合修复 76.0\%／并集全败 0.8\%）。对全部 14{,}400 条 MATH 判定的版本化端点敏感评分器的一次重执行改变了其中 14 条——全是单一任务上 v1 对区间端点答案的错误拒绝；v1 重放本身内部一致，而更早存储的零翻转产物未能由修正分析复现，已被取代。因此新评分器旨在捕获的括号合并缺陷确实在此存档中触发，且恰在一个任务上。

\subsection{隔离的 MATH 提示协议试运行}第一，干净协议的多样性结果在第二个领域、不同输出空间上得到重复。第二，一个被隔离的试运行轮次提供了一项探索性比较：当相同六个构建器（被错误地）收到数值答案格式与 MATH-500 不匹配的 GSM8K 风格任务描述时，生成种群仍保持行为多样（16.2\% 分歧，19 个唯一结果向量），但其联合修复坍缩至 18\%——对灾难性成员的代码级检查逐字复现了 Phase-I 轨迹分类（一个先生成后验证的 harness，其验证器拒绝几乎所有答案，其回退返回过时的循环变量或 ``0''）。有多样性而无效用，由代码级检查不可见的提示侧协议错误诱发：检测到它的是测量任务本身，而非任何代码级审核。
