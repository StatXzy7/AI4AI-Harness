\begin{abstract}
自动生成的 LLM harness 提供了丰富的设计空间，但其源代码、执行机制和结果差异需要分别测量。我们提出一个以证据为先的诊断框架，并在 BIRD 文本转 SQL 任务上研究这一问题。发现阶段的轨迹检查区分了机制缺失、分支未触发和实现失效；在 1,169 道题上，自由生成产生了 8.6 个百分点的观测 oracle 提升空间。一个单种子的 MATH-500 探查提供了跨领域压力测试，观察到 10.6\% 的结果差异和 4.75 个百分点的提升空间。我们进一步形式化单次运行 oracle、稳定排序、稳定互补性和预算约束效用之间的区别，并将其组织为五类分别报告的命题。离线流程通过排序不变性、支配关系与互补性区分、克隆重复和条件混合控制进行检查，并以哈希绑定的挑战重执行验证；该流程也修正了我们早先的一项验证性表述。在存档析因研究中，组合筛选干预的估计为 $\RevisionPrimaryDelta$ 个百分点（95\% CI $\RevisionPrimaryCI$），因此当前数据支持测量与诊断贡献，而不足以支持干预优越性结论。该框架为把表面多样性转化为可复核、可审计的证据提供了实践路径，并明确了形成群体级部署结论所需的后续对照。
\end{abstract}

\subsection*{AI 使用声明}
本研究借助 AI 研究 AI 生成的产物，以下说明其参与范围。

\textbf{必要披露。}生成式 AI 工具用于：（i）编写和修改实验代码，包括生成流程、评估采集器和统计分析脚本；（ii）运行涉及模型 API 调用的实验流程；（iii）分析数据并制作图表；（iv）起草和修改论文。修订后的主分析表、析因表和结果图由共同的版本化重分析产物生成。历史探索性分析保留各自来源与局限；审后修正与原协议分开记录。验证记录分别说明各产物的自动测试、开发控制与审核范围。审后修订也使用了同模型子代理审核；这些属于机械检查，不构成跨模型独立科学验证。开发控制和本机运行测试不能证明独立门控校准或提供方层面的执行独立性。

\textbf{研究构思与方向。}核心问题、因果设计决策（估计目标、对比与排除规则）、解释标准及拟议的继续／停止准则在 AI 协助下形成。人类作者确定总体研究方向并要求按审稿意见修订；AI 工具也提出了分析与实验设计、识别反例并实施修订。最终科学决策及投稿批准仍由作者负责。本声明不表示每项 AI 提议均已得到作者逐项批准。
