\begin{abstract}
自动生成的 LLM harness 可能在源代码和观测结果上不同，却并不带来稳定的任务专长。我们研究如何区分依赖程序的专长与重复执行的收益，把源代码、执行与结果多样性作为三个不同的量分别报告。在 BIRD 文本转 SQL 的案例研究中，轨迹检查发现了三条执行层面的路径，说明表面不同的 harness 为何没有实现不同的策略：声称的机制在控制流中缺失（12 个生成候选中的 6 个）、机制存在却从未被触发（\react，10/10）、多轮路径损坏（1/12）；代码相似度与结果不一致之间没有秩相关（$\rho=-0.01$；尽管全部通过代码差异检查，仍有 21/66 个生成对具有完全相同的正确性向量）。在 MATH-500 上一项独立的探索性研究（35 个生成 harness、400 个任务、各运行一次）显示，相对于最佳固定成员（即 \bare{} 本身）有 $4.75$\,pp 的单次 oracle 余量。随后一项新的预注册采集把八个生成 harness 与九个逐字节相同的 \bare{} 克隆槽配对，各三次独立重复：尽管克隆群体按构造没有专长，重复平均的描述性插件量在两臂上都为正（真实面板的 350 个完整任务上 $2.54$\,pp，克隆臂的 383 个完整任务上 $2.67$\,pp）。交叉拟合的冻结选择增益为 $G_{\rm real}=0.17$\,pp（95\% CI $[-0.82,1.31]$），而 $G_{\rm clone}=0.55$\,pp，故克隆校准差为 $-0.10$\,pp（95\% CI $[-1.55,1.46]$，随机化 $p=.7742$），基于 342 个配对完整任务；覆盖门控未通过（12.5\% 的真实臂任务被排除，高于冻结的 10\% 阈值），因此面板报告 \textsc{Insufficient Evidence}（证据不足）——既非存在增益，也非 $1$\,pp 等效。综合而言，这些研究表明生成 harness 群体中观测到的 oracle 覆盖增益混合了程序专长与对同一固定随机程序额外执行的收益；harness 群体评估应把单次覆盖机会、重复稳定交互与执行前选择价值作为不同的量报告。
\end{abstract}

本研究按构造就是一个借助 AI 研究 AI 生成产物的项目，以下精确披露 AI 协助的范围。

\textbf{必要披露。}生成式 AI 工具用于：（i）编写和修改实验代码（生成流程、评估采集器、统计分析脚本）；（ii）运行涉及模型 API 调用的实验流程；（iii）分析实验数据并制作表格和图；（iv）起草和修改论文文字。修订后的主分析表、析因表和结果图由共同的版本化重分析产物生成。历史探索性分析保留各自原始来源与所述局限。审后修正与原协议分开记录。验证记录分别说明各产物的自动测试、开发控制与审核范围。审后修订也使用了同模型子代理审核；这些属于机械检查，不构成跨模型独立科学验证。开发控制和本机运行测试不能确立独立门控校准或提供方层面的执行独立性。
