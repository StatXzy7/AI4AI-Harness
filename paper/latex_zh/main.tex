\begin{abstract}
当一组 LLM harness 相比其中表现最好的单个成员能够解决更多任务时，这种增益究竟来自真正的程序专长，还是仅仅来自更多次获得正确答案的机会？本文从两个互补角度研究这一问题。在 MATH-500 上，我们将生成的 harness 与字节级完全相同程序的重复执行进行比较。结果表明，即使九个执行槽运行的是完全相同的 single-call 程序，其重复平均后的 oracle headroom 仍达到 $\WpVthreeClonePlugin$ 个百分点，说明正的覆盖增益本身不足以证明程序之间存在专门化能力。在 BIRD 上，我们进一步考察源代码层面的差异是否真正转化为不同的执行行为。轨迹分析揭示了多种失效模式：部分声称存在的机制实际上并未实现，部分机制虽然存在却从未被触发，还有一些机制虽然执行，却反而破坏了最终输出。综合来看，这些结果为 LLM harness population 的评估提供了一个更清晰的证据框架：应分别检验代码层面的差异、实际执行行为、稳定的任务优势以及这些优势能否被有效选择和利用，从而更准确地判断生成程序群体所带来的真实收益。
\end{abstract}
