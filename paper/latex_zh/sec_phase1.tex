Phase I 是一项发现研究：其作用是确立现象、分类与题目侧提升空间的存在，并为验证性设计提供动机。其任何结果都不是验证性的：151 个评估项中有 24 个与协议开发测量重叠，人工控制是在检查开发轨迹后设计的，其评分器是一个保守代理（附录~\ref{app:phase1-provenance}）。我们在明确这些限制的前提下报告它。
\subsection{Harness、结果与三项指标}\label{sec:metrics}
\textbf{Harness} $H$ 包裹一个冻结的目标模型 $M$：它接收自然语言任务 $x$，对 $M$ 发起一次或多次调用，可选地执行中间产物（如 SQL），并返回以程序化方式评分的最终答案。以 $H_0$ 为单次调用的 bare 基线、$Y\in\{0,1\}$ 为正确性，\textbf{harness 边际价值}为
$\Delta(x,H,M) = Y(x,H,M) - Y(x,H_0,M) \in \{-1,0,+1\}$
（$+1$ 为修复，$-1$ 为 harness 引入的损害）。

我们建议 harness 生成与 harness 路由流程在留出集上报告三项前提指标，它们都可从任何评估本就产生的结果矩阵计算：\textbf{（i）成对结果分歧}——在所有 harness 对上，正确性不同的题目比例；\textbf{（ii）联合修复率}——bare 错题中被某个种群成员修复的比例；\textbf{（iii）包含 bare 的 oracle 提升空间}——在留出题目 $x_1,\dots,x_n$ 上，
\[
H(P) \;=\; \frac{1}{n}\sum_{i=1}^{n} \max_{H \in P \cup \{H_0\}} Y(x_i, H)
\;-\; \max_{H \in P \cup \{H_0\}} \frac{1}{n}\sum_{i=1}^{n} Y(x_i, H).
\]
正的观测提升空间记录的是该执行矩阵中依题目而异的成功；要确立稳定的路由信号需要独立重复。有分歧而无修复，不增加超出 bare 的观测覆盖；有修复而无提升空间，不增加超出最佳固定成员的观测 oracle 优势。

\subsection{坍缩的量化}\label{sec:collapse}
领域为 BIRD 文本转 SQL（SQLite；执行准确率评分），整个 Phase I 目标冻结为 \textbf{GLM-5.3-Flash}（温度 0）。在首日种群——14 个 harness（\bare、\react{} 与 12 个演化候选）$\times$ 60 道题——上，平均成对结果分歧为 \textbf{3.3\%}，且 \textbf{91 对中有 36 对在每道题上都相同}；仅看 12 个生成候选（66 个候选对；原代码差异检查的归一化字符指标下平均成对代码相似度 0.143），分歧为 3.8\%，21 对完全相同。每个候选都通过了代码差异检查（“所有文件互不相同，差异非平凡”）。对 bare 错题的联合修复率为 7.7\%，oracle 提升空间为 3.3\,pp；\react{} 与 \bare{} 在零道题上有差异。

图~\ref{fig:phenomenon}（附录~\ref{app:phase1-provenance}）把核心关系定量化：在全部 91 对上，该图 token 序列指标下的源代码相似度与结果分歧的 Spearman $\rho = -0.010$——代码相似度在此与行为相似度\emph{没有观测到秩关联}。（各对相互重叠；$\rho$ 是描述性的，不是推断性的。）

\subsection{轨迹分类：代码多样性为何未能成为行为多样性}\label{sec:taxonomy}
审核执行轨迹把“不同代码”分解为三类失败：\textbf{T1——机制被描述但未执行（6/12 个候选）}：一次调用，不执行任何产物（与 \bare{} 路径相同；文档字符串宣称的检索或自检并不存在）；\textbf{T2——机制存在但未触发（\react，10/10 道题）}：第一条 SQL 即成功，因此错误修复从不触发，最终 SQL 与 \bare{} 相同（这并不表明修复路径在失败时缺乏因果作用）；\textbf{T3——多轮路径失效（1/12）}：自然语言散文被当作最终 SQL 返回，把 bare 答对的题变成 harness 答错。T1 需要执行路径准入门控，T2 需要受控故障，T3 需要可执行输出验证。

\subsection{人工正控制：提升空间确实存在}\label{sec:positive}
四个手写 harness 具有强制区分的执行路径（执行后修复；三票投票；模式链接；提示前置重排），使用相同的冻结目标与评分器，在 60 道题上给出 \textbf{6.67\,pp} 的 oracle 提升空间，在 151 题集合上为 \textbf{7.28\,pp} {[}3.3, 10.0{]}，且每个机制都修复了其他机制漏掉的题。该控制是在检查首日轨迹后设计的，因此其提升空间是描述性的，不是盲测的；\bare{} 自身在两次温度 0 的首日运行之间翻转了 60 题中的 3 题。
