\subsection{代码多样性却无行为多样性：BIRD}
\label{sec:f1-collapse}
该发现群体包含 $14$ 个 harness——$12$ 个演化生成的候选加上 \bare{} 与 \react{} 基线——在 $60$ 个 BIRD 任务上各有一次记录执行（单运行矩阵；此处未采集匹配重复），目标模型冻结为 \texttt{GLM-5.3-Flash}。成员配对给出 $\binom{12}{2}=66$ 个生成候选对，计入两个基线后为 $91$ 对。每个候选此前都通过了代码差异检查，断言所有文件互异且差异非平凡。然而，$66$ 个生成对中有 $21$ 对在每个任务上的正确性向量完全相同（计入基线后 $91$ 对中有 $36$ 对）；在全部 $91$ 对上，源代码相似度与结果不一致之间基本没有秩相关（Spearman $\rho=-0.010$；图~\ref{fig:phenomenon}）。总体平均成对结果不一致为 $3.3\%$（生成候选间 $3.8\%$），对 \bare{} 错误的联合修复率为 $7.7\%$，单次 oracle 余量为 $3.3$\,pp；\react{} 与 \bare{} 在零个任务上不同。

\begin{figure}[t]
\centering
\includegraphics[width=0.60\linewidth]{figures/fig_phenomenon.pdf}
\caption{\textbf{代码多样性与行为坍缩}（BIRD 发现群体：$14$ 个 harness $\times$ $60$ 个任务，计入 \bare{} 与 \react{} 共 $91$ 对）。每个点是一对 harness；$x$ 为 token 序列代码相似度，$y$ 为正确性不同的任务比例。代码相似度不能预测结果不一致（$\rho=-0.010$），且 $36/91$ 对在全部 $60$ 个任务上完全相同。}
\label{fig:phenomenon}
\end{figure}

审计执行轨迹分离出三条路径，说明不同的源代码为何没有产生不同的被执行策略。\textbf{T1——声称却未执行的机制}（$6/12$ 个生成候选）：程序只发起一次模型调用、不执行任何产物，与 \bare{} 是同一条执行路径，而其 docstring 却声称控制流中并不存在的检索或自检机制。\textbf{T2——存在却从未被触发的机制}（\react{} 在审计的 $10/10$ 个任务上）：错误修复分支是真实代码，但首个 SQL 在每个审计任务上都成功，分支从不触发，最终 SQL 与 \bare{} 相同；这并不表明修复路径在失败时缺乏因果作用力。\textbf{T3——损坏的多轮路径}（$1/12$）：一个执行-检查-修复程序把模型的散文当作最终 SQL 返回，使 \bare{}-正确的题目变成 harness-错误。三类分别要求不同的检验——执行路径准入、受控故障注入、可执行输出验证。

一个人工正控表明该测量装置能够检出真正的专长。四个在同一冻结目标与评分器下、强制具有不同执行路径的手写 harness（执行并修复、三票、schema 链接、提示优先重排），在 $60$ 个任务上给出 $6.67$\,pp 的 oracle 余量，在完整的 $151$ 题集合上为 $7.28$\,pp（95\% 区间 $[3.3,10.0]$），每个机制都修复了其他机制漏掉的题。由于该控制是在检查发现轨迹之后才编写的，其余量是描述性的而非盲测；发现群体的来源（含 $24/151$ 个题目与协议开发重叠、以及保守的代理评分器）在附录~\ref{app:phase1-provenance} 报告。

\subsection{探索性 MATH-500 群体中的单次余量}
\label{sec:f2-headroom}
在 MATH-500 上一项独立的探索性研究使用六个构建器、一个种子、一个机制无关的有效性门控，目标冻结为温度 0 的 \texttt{GLM-5.3-Flash}，每个被纳入的 harness 在相同的 $400$ 个评估任务上执行一次。$48$ 个生成槽中纳入 $35$ 个；两个推理密集型构建器在多数槽上耗尽了 $32$k 生成 token 预算，因此该群体对推理密集风格的代表性不足。这是一个复制探针而非析因实验，既未采集重复也没有同代码对照。

该群体表面上行为多样：平均成对结果不一致为 $10.6\%$（最大 $33.0\%$），$36$ 个成员（计入 \bare{}）中有 $33$ 个具有唯一正确性向量，成员修复了 $76.0\%$ 的 \bare{} 错误。但单次 oracle 覆盖率为 $98.50\%$，而最佳\emph{固定}成员是 \bare{} 本身，仅 $93.75\%$；每个生成成员单独看都更差（$0.6825$--$0.915$）。因此含 bare 的单次 oracle 余量为 $4.75$\,pp：这是一个无法通过执行前承诺于任何单一程序来实现的覆盖机会。这一探索性观察促成了 \S\ref{sec:f3-clones} 中独立的预注册重复加克隆研究；两项研究使用不同的群体、估计目标与预算，$4.75$\,pp 不与受控结果作为前后校正来比较。第二域复制详见附录~\ref{app:crossdomain}。

\subsection{同代码克隆呈现正的表观互补性}
\label{sec:f3-clones}

重复平均的描述性插件在\emph{两}臂上都为正——真实面板的 $350$ 个完整任务上 $\WpVthreePlugin$\,pp，克隆臂的 $383$ 个上 $\WpVthreeClonePlugin$\,pp——尽管克隆群体按构造有 $H_{\rm stable}=0$。这是本文最锐利的测量事实：相同源代码、相同重复计划、正的表观互补性，与已知真值零假设对最大化型插件的预测完全一致。

交叉拟合的冻结选择增益在两臂各自完整任务集上为 $G_{\rm real}=\WpVthreeG$\,pp（CI $\WpVthreeGCI$）与 $G_{\rm clone}=\WpVthreeGclone$\,pp，因此克隆臂上的有限 $(R,T)$ 选择噪声与面板增益同量级。判定统计量 $D$ 并非这些臂级数值的算术差：两个增益都在两臂均完整的 $\WpVthreeNPaired{}$ 个任务上通过交叉拟合重算，得到 $D=\WpVthreeD$\,pp（CI $\WpVthreeDCI$，随机化 $p=\WpVthreeP$）。稳定成员排序（C-rank）为\textsc{Supported}（成立），但互补性判定弃权：$\WpExclReal\%$ 的真实臂任务不完整，高于冻结的 $10\%$ 覆盖门控，故 C-comp 为\textsc{Insufficient Evidence}（证据不足），区间上端不能确立 $1$\,pp 等效，被排除任务的全 0／全 1 填充情景把 $G$ 框在 $\WpVthreeBounds$\,pp。该弃权既由功效、也由覆盖率驱动：在 $R=3$ 时，该仪器即便对一个强的 $H=17.5$\,pp 双专家交叉也只有 $0\%$ 功效（$R=5$ 时 $0.7\%$，$R=10,20$ 时 $100\%$；\S\ref{sec:protocol}）。

槽数不决定花费。离线的等执行预算回放把 dev 排序后面板的执行后 oracle 覆盖与 $27$ 次同代码执行中的 $b$ 次对照，$b\in\{3,9,15,27\}$：面板减同代码的差为 $+0.37, +0.03, -0.11, -0.25$\,pp，即在每个预算上都持平（范围 $-0.25$ 至 $+0.37$\,pp）。该面板使用了克隆臂 $3.73\times$ 的 token（$54.17$M 对 $14.51$M，$22{,}192$ 对 $10{,}800$ 个逻辑调用），因此不做任何已实现成本匹配的主张；由于两臂输出格式不兼容（带框数字对自由散文），也不报告跨臂多数投票准确率。冻结的执行前选择器 $\pi_Z$ 在每个评估任务上都弃权为 \bare{}，与 dev 固定在三次重复上的 $\WpBareAcc\%$ 持平（探索性研究中 \bare{} 的单次准确率为 $93.75\%$；此处更高的值是同一任务集上的重复均值，是不同的统计量，并非矛盾），而预先固定一个随机成员则显著更差（$\WpRandomDiff$\,pp，CI $\WpRandomCI$）：观测到的 oracle 价值并不是已实现的路由价值。

\subsection{BIRD 上的准入策略研究}
\label{sec:f2-admission}
一项独立的确认性 BIRD 研究让六个独立构建器与三个种子在策略强制（来自固定集合的具名机制对自由发明）与合规门控两个因素下交叉，给出四个臂：II-A（自由、无门控）、II-B（自由、门控）、II-C（强制、无门控）、II-D（强制、门控）。评估覆盖开发期间从未打开过的九个数据库中的 $1{,}169$ 个问题（一个已披露的 $18$ 题冒烟测试例外），使用官方 BIRD 执行评分器，分析在结果前冻结、之后以版本化校正重分析重跑。所实现的门控把非平凡机制的\emph{结构性筛除}与合规验证捆绑在一起——八个强制提示转换槽中有两个即便中性有效也无法通过——所以该处理不能在因果上分离出"验证"本身。
