Phase II 是验证性研究。其协议在观察到任何验证性结果之前即冻结并提交（一个例外：18 题流水线冒烟测试，其聚合准确率曾被观察且题目被保留，在协议变更日志中作为偏差 D1 披露）；偏差均记录于协议变更日志（附录~\ref{app:phase2-protocol}）。以下概述冻结的估计目标、划分、仪器与分析计划。
\subsection{设计}\label{sec:p2design}

\paragraph{实验组。}两个交叉因素：\emph{策略强制}（S=1：构建器被指派固定八种机制中的一种具名机制；S=0：构建器在不指定机制的情况下自行发明改进）与\emph{一致性门控}（G=1：harness 必须通过冻结的一致性套件；G=0：仅中性有效性）。这给出四个析因组，记为 \textbf{II-A}（自由／无门控）、\textbf{II-B}（自由／有门控）、\textbf{II-C}（强制／无门控）、\textbf{II-D}（强制／有门控）。第五个预先指定的\emph{次要}组 \textbf{II-E}（开放机制发现：构建器在通用轨迹原语上发出自行指定的行为合同，按其自身声明门控）检验机制多样性是否根本需要作者供给的词汇；它被有意置于析因之外。每个单元有八个槽位：强制组中为八个被指派机制，自由组中为同一自由提示的八次独立生成。在有门控自由组（II-B）中，构建器从固定的四词词表（\texttt{repair}、\texttt{vote}、\texttt{twostage}、\texttt{plain}）发出自行声明的机制；门控对照轨迹验证声明的场景。这些声明比强制合同窄，且该映射是操作性的、未经独立校准（附录~\ref{app:gatecontrols}），因此 B 组种群不是 A 组的嵌套子集，产出也不必有序。这些组名专用于 Phase II；\S\ref{sec:phase1probes} 中的 Phase-I 条件一律以其描述性名称指代。

\paragraph{实际实施的处理；共同尝试上限。}原门控把 \texttt{hint\_guard} 与 \texttt{format\_guard} 都映射为返回 \texttt{NO\_MECHANISM\_declared} 的普通场景；准入要求 \texttt{PASS}。因此八个强制策略槽位中的两个即使中性有效也无法通过，并且两个强制组中都没有 \texttt{format\_guard} 候选通过中性有效性（一项提取审计发现内嵌 SQL 围栏会截断本属有效的 Python，附录~\ref{app:extraction}）。我们把 G 解释为\emph{非平凡机制筛选加一致性验证}；存档结果不能识别纯验证。每个槽位至多有 $R{=}3$ 次原始构建尝试（同一模型，温度 0.7，16{,}384 token 上限），首次接纳即停；A/B/C/D 记录的原始尝试总数为 269/255/273/324，token 成本未完整恢复。槽位失败即终局（不补足），因此生成可靠性是处理的一部分，并通过三个比率单独报告（附录~\ref{app:phase2-protocol}）。

\paragraph{构建器与种子。}六个来自独立实验室的构建器（GLM-5.3、Qwen3.8-Max、DeepSeek-V4-Pro、Kimi-K3、MiniMax-M3、ERNIE-5.0-Thinking-Preview），各三个种子：18 个配对（构建器 $\times$ 种子）单元——即项目单一 API 网关上最强的模型；当时无法访问 Anthropic 或 OpenAI 家族的构建器，因此前沿能力依赖性未经检验。每个单元都进入主对比，无论接纳种群大小如何，包括 $K{=}0$；排除低产出单元会以处理后结果为条件。

\paragraph{数据隔离。}一个失败即关闭的污染登记器扫描每个项目产物中曾被观察的 BIRD 题目。开发期间接触过的两个数据库被整体禁用；验证性评估使用\textbf{来自九个开发期间从未打开过的数据库的 1{,}169 道题}，另有一个在结果出现前抽取的分层 400 题核心集（跨九库按比例分配，种子 20260904；未使用任何结果变量；不声称预训练时段隔离；18 题冒烟接触是已披露的例外）。析因次要分析在全部四组上使用相同核心题。

\paragraph{评分器。}主评分器：官方 BIRD 执行评分器（原始结果行的集合相等，30\,s 墙钟超时）。次要评分器：Phase-I 旧评分器，经测量一致地保守（在 Phase-I 矩阵上它从不把官方评分器判错的答案判对）。

\paragraph{仪器。}一致性套件以脚本场景驱动每个 harness，并对记录的执行轨迹断言，从不针对任务表现，因此门控不会泄漏结果监督。每个机制都用\emph{成对反事实变体}探针探测，这些变体的正确答案不同——包括第一个查询\emph{成功}的变体，以把条件修复与无条件第二次调用区分开。仪器以手写正／负控制校准，并在每批生成前重跑（图~\ref{fig:design}，附录~\ref{app:phase2-protocol}）。

\subsection{冻结分析计划}\label{sec:p2plan}
\textbf{主估计目标}是完整 1{,}169 题集合、官方评分器下，（构建器 $\times$ 种子）单元上包含 bare 的 oracle 提升空间的配对差 $H(\text{II-D}) - H(\text{II-A})$——一个连续效应，配双侧 95\% CI 与配对置换检验，绝不设通过／失败阈值。对角对比是主要的，因为两个因素在生成流程中是一起部署的；主效应与交互作为次要项将其分解。Phase-I 阈值仅作为描述性清单保留。
\textbf{验证性次要项}（Holm 校正，全部四组在相同 core-400 题上）：门控主效应 $[(B{-}A)+(D{-}C)]/2$、策略主效应 $[(C{-}A)+(D{-}B)]/2$，以及二者交互 $(D{-}C)-(B{-}A)$——即策略差异化是否需要执行保真才能实现。
\textbf{原计划与修正后的推断}：原代码漏掉了库内题目重采样，只重采样单元摘要。版本化的审后分析在全部组与单元间使用 10{,}000 次共享的数据库／库内题目抽取，构建器保持固定，在构建器内部重采样生成种子；它不加入执行重复方差，而每个构建器只有三个种子，种子成分可能低估真实生成变异（一项已报告的数据限制）。
精确符号翻转参考检验以观察到的题目为条件、以单元对比的符号对称性为条件（主检验单侧；次要检验双侧并作 Holm 调整）——不是随机化因果检验。$H(P)$ 对 $K$ \emph{不}单调——加入一个全对的 harness 会把提升空间驱向零——因此是匹配 $K$ 比较、而非单调性，许可跨种群主张。K 匹配敏感性、完整估计目标定义与稳健性审核（双评分器、关缓存复现、重复稳定性）连同协议偏差日志在附录~\ref{app:phase2-protocol} 中规定。
