Phase II 是验证性研究。协议在观察验证性结果前冻结并提交，但存在协议偏差日志 D1 披露的例外：18 题流水线冒烟测试的聚合准确率曾被观察，题目仍被保留。偏差均记录于变更日志（附录~\ref{app:phase2-protocol}）。以下概述冻结的估计目标、划分、仪器与分析计划。
\subsection{设计}\label{sec:p2design}
\paragraph{实验组。}交叉设置两个因素：\emph{策略强制}（S=1：从固定八种机制中指定一种；S=0：不指定机制，由构建器自行改进）与\emph{一致性门控}（G=1：须通过冻结的套件；G=0：仅检查中性有效性）。四组为 \textbf{II-A}（自由／无门控）、\textbf{II-B}（自由／有门控）、\textbf{II-C}（强制／无门控）、\textbf{II-D}（强制／有门控）。预先指定的次要组 \textbf{II-E} 为开放机制发现：构建器用通用轨迹原语自行声明行为合同，再按其声明门控，用于检验机制多样性是否需要作者给定词汇；它不属于析因设计。这些名称专用于 Phase II，Phase-I 条件使用描述性名称。
\paragraph{实际实施的处理。}原门控将 \texttt{hint\_guard} 和 \texttt{format\_guard} 映射到返回 \texttt{NO\_MECHANISM\_declared} 的普通场景，而准入要求 \texttt{PASS}。因此，八个强制策略槽位中的两个，即使中性有效也无法通过。G 应解释为\emph{非平凡机制筛选加一致性验证}；存档结果无法识别纯验证作用，匹配种群规模也无法恢复被排除的类型。另外，两个强制组各18个\texttt{format\_guard}槽位、54次尝试均未通过中性有效性检查，发生在机制门控之前。代码提取审计发现一种可能的上游失败：内嵌SQL围栏会截断原本有效的Python代码（附录~\ref{app:extraction}）。
\paragraph{相同尝试上限，实际成本不等。}每槽位最多 $R=3$ 次原始构建尝试，使用同一模型、温度 0.7、16,384 token 上限，首次接纳即停止。原协议的“恰好三次”不符合实际执行。A/B/C/D 的日志原始尝试数为 269/255/273/324，每组上限 432；实际 token 成本尚未完整恢复。各组的生成提示和准入策略不同：无门控组接纳首个中性有效候选（可解析、可导入、在一道开发题上返回 SQL，不检查机制）；有门控组额外要求通过一致性套件。槽位失败后不补齐种群，生成可靠性因此也是处理的一部分。已保存提取后的代码文件与尝试日志，但生成器未存档完整构建器回复。三项生成率单独报告：$R_{\mathrm{artifact}}$ 为有效产物率，$R_{\mathrm{contract}}$ 为有效且非空洞的合同率，$R_{\mathrm{fidelity}}$ 为在合同有效条件下声明属性得到验证的比例。
\paragraph{构建器与种子。}六个独立实验室的构建器为 GLM-5.3、Qwen3.8-Max、DeepSeek-V4-Pro、Kimi-K3、MiniMax-M3、ERNIE-5.0-Thinking-Preview，各三个种子，共 18 个配对单元。它们是项目单一 API 网关当时可用的最强模型；无法访问 Anthropic 或 OpenAI 家族构建器，因此尚未检验对这些模型能力的依赖。所有单元均进入主对比，包括 $K=0$；排除低产出单元会以处理后的结果为条件。
\paragraph{数据隔离。}污染登记器扫描项目产物中曾观察过的 BIRD 题目，并在检查失败时拒绝继续。开发阶段接触的两个数据库整体禁用；验证集包含九个数据库的 \textbf{1,169 道题}。除已披露的 18 题冒烟接触外，九库未用于项目协议开发；登记器能支持的是没有项目特定的自适应使用，不能保证训练数据隔离。分层抽取的 400 题核心集在结果出现前确定，四组析因次要分析使用相同题目。
\paragraph{评分器。}主评分为官方 BIRD 执行评分器，对原始结果行做集合相等比较，墙钟超时 30 秒。次要评分为 Phase-I 旧评分器；在 Phase-I 矩阵中的检查显示，它相对官方评分器一致偏保守，没有把官方判错的答案判对。
\paragraph{测量仪器。}一致性套件以脚本场景驱动 harness，断言所记录的执行轨迹，不依据任务成绩，避免以结果监督进行准入。机制探针使用正确答案不同的成对反事实变体，其中包括首条查询成功的变体，以区分条件修复与无条件第二次调用；输出按精确的归一化相等比较。在 Phase-II 生成前，套件以三个人工正控制（均须通过）、两个已知伪机制负例（均须拒绝）及 bare 必须违反每个条件属性的不变量进行校准；每批生成前重跑校准。II-E 还运行 bare 检查合同非空洞性，即 bare 必须违反该属性，并仅验证实际声明的属性。

\subsection{冻结分析计划}\label{sec:p2plan}
\textbf{主估计目标}为完整 1,169 题、官方评分器下，18 个构建器乘种子单元中包含 bare 的 oracle 提升空间配对差 $H(\mathrm{II\!\!\!-D})-H(\mathrm{II\!\!\!-A})$，报告连续效应、双侧 95\% CI 和配对置换检验，不用通过／失败阈值。Phase-I 阈值仅保留为描述性清单。\textbf{验证性次要目标}在共同 core-400 上包括门控主效应 $[(B-A)+(D-C)]/2$、策略主效应 $[(C-A)+(D-B)]/2$、交互 $(D-C)-(B-A)$，三项检验经 Holm 校正。

\textbf{原计划与修正推断。}原主分析代码漏掉库内题目重采样，且各单元分别采样题目；原析因代码仅重采样单元摘要。审后版本化分析在全部组和单元之间共用 10,000 组数据库／库内题目抽样，固定构建器，在各构建器内重采样生成种子。它未增加执行重复方差。精确符号翻转参考检验以已观察题目为条件，并假设单元对比的符号对称；主检验单侧，次要检验双侧且经 Holm 校正，均非随机化因果检验。$H(P)$ 不随 $K$ 单调增加：加入全对成员会令提升空间降至零。因此跨种群比较应依据匹配 $K$ 的分析，不能依据单调性。K-matched 敏感性、完整定义、双评分器／关闭缓存／重复稳定性审核及偏差日志见附录~\ref{app:phase2-protocol}。
