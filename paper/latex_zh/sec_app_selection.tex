\section{冻结选择器与等执行次数重放}\label{app:selection}
本节对应新的 MATH 重复研究：选择器在 $100$ 道开发题上拟合，在 $400$ 道评估题上评分。旧档案的 $80/320$ 划分和 BIRD 数据库划分选择分析属于历史分析，分别见附录~\ref{app:archive-analysis} 和~\ref{app:rich}。

\subsection{冻结特征选择器}$\pi_Z$ 是在 TF-IDF 题目特征（最多 300）与仅在训练折内计算的逐成员开发准确率上的多项 logistic 回归；在 100 道开发题上作 5 折题目级 CV，同题重复绝不跨折拆分；折模型平均；并列以成员 id 打破；当 top-2 概率差距低于 0.15 时弃答至 \bare{}。重复聚合使用逐成员—题的可用重复均值（同题重复留在一折）。比较器：\bare{}、开发固定、预先固定随机成员（带种子）、M1b（缺失单元上带 single-call 回退的开发固定）。$E_1$（预算按构造满足）不适用，因为面板成员发起不止一次调用；$b{=}3$ 次逐题调用的 $E_b$ 作为单独命名的估计目标报告。泄漏控制：不使用答案、正确性、评估派生难度、执行后轨迹或评分器特征。

\subsection{选择与预算效用的诊断定义}D 类评估一个冻结的确定性政策 $\pi_Z: Z(x)\mapsto h$——执行前特征（题目文本、冻结机制标签、训练折开发准确率），仅在开发任务上拟合——按 $D(\pi_Z)=\mathbb{E}_x[Y(x,\pi_Z(x))-Y(x,h_{\rm dev\text{-}fixed})]$，并带弃答规则：当 top-2 选择概率差距低于冻结边界时回退到 \bare{}。E 类在均匀逐任务调用预算 $b$、$\lambda{=}1$ 损害加权（一次回归抵消一次修复）下评估 $U_b(\pi)=\mathbb{E}_x[\Delta(x,\pi(x))]$；仅当逐记录证据在每个被评估成员—任务对上验证预算时它才可受理，否则弃答。

\subsection{等执行次数重放与实际采集账目}
报告三种不同的比较且绝不混淆。(i) \emph{等槽位采集}：两臂都执行九个成员／槽位、三次重复；这是随机化设计，不意味着匹配花费。(ii) \emph{共同逐任务执行预算}（\S\ref{sec:selection-result}）：在 $b\in\{3,9,15,27\}$ 次逐任务执行下，离线比较开发排序面板组合与 27 次同代码执行中的 $b$ 次，仅采用执行后\emph{oracle} 聚合；面板减同代码的 oracle 差为 $+0.37,+0.03,-0.11,-0.25$\,\%。由于两臂输出格式不兼容（带框数字对自由散文）、模态答案键不公平，不报告跨臂多数投票准确率。(iii) \emph{已实现花费}：逐请求账目分层为实验运行 $>$ harness 执行 $>$ 逻辑调用 $>$ 提供方尝试；迁移副本排除。真实臂作出 22{,}192 次逻辑调用（32{,}097 次提供方尝试；54.17\,M 已知 token；每评估题 54.5 次调用），而克隆臂为 10{,}800 次逻辑调用（10{,}804 次尝试；14.51\,M token；每题恰好 27 次）——由多调用面板成员驱动的 $2.05\times$ 调用比与 $3.73\times$ token 比；在冻结盈亏平衡价下的保守上限为 1{,}803.82 对 483.15 元人民币（定价不可独立验证；报告为 token 数乘以冻结的每 1M token 33.3 元，绝不作为计费金额）。全部臂的总计：\WpLogicalCalls{} 逻辑调用、\WpHttpAttempts{} 尝试、\WpTotalTokens{} 已知 token、\WpCostCny{} 元上限。因此我们不作已实现成本匹配主张；共同预算重放仅匹配 harness 执行次数，不匹配 token 成本。
