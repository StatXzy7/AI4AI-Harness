LLM harness 是包裹冻结模型的一组提示、工具与控制流程程序。自动生成大量这类程序带来一个评估问题：什么证据能够说明一个新程序提供了新能力？不同代码可能执行相同路径；不同路径可能给出相同答案；而一次运行中不同的答案可能反映执行随机性，并非可重复的优势。

我们在 BIRD 文本转 SQL 任务上研究这一问题 \citep{bird2021}。在 Phase-I 发现种群中，66 对生成候选中有 21 对的正确性向量完全相同（计入 \react{} 与 \bare{} 后，91 对中为 36 对），而代码相似度与结果分歧没有秩关联（$\rho=-0.01$）。轨迹检查发现三种情形：宣称的机制不在控制流中、机制存在但未触发、多轮实现失效。这些观察促使我们审核测量流程；它们并不证明生成的 harness 普遍坍缩。

后续一项预先指定的析因研究在六个构建器、三个种子上交叉设置策略强制与一致性门控。其主评估使用协议开发之外九个数据库的 1{,}169 道题，另有一项已披露的 18 题冒烟测试例外。在这一修订后的设置下，无门控自由生成已产生 8.6\,pp 的观测 oracle 提升空间；Phase-I 的模式没有重现，但生成方式、评分器、数据与执行均发生变化，缺少受控桥接实验时不能归因于任一协议组件。门控还改变了可接纳的策略空间：两种允许的单次调用提示变换无法通过其机制检查。我们保留该实验并报告版本化的审后重分析；主对比仍为 $\RevisionPrimaryDelta$\,pp（95\% CI $\RevisionPrimaryCI$），既未证明改善，也未确立等效性。

我们在当前阶段的贡献是一种带有校准统计保证的测量方法，加上两个实证案例研究：
\begin{enumerate}
\tightlist
\item \textbf{代码、轨迹与结果多样性各不相同。}发现阶段的例子说明，为何未激活的分支与缺失的机制需要不同的检验。
\item \textbf{准入与推断定义了比较的含义。}一项析因研究及其数据与统计链条的明确修正，说明实际被评估的是哪项干预、其估计支持什么。
\item \textbf{观测 oracle 价值不是稳定或可用价值。}重复不稳定性要求分别报告 oracle 准确率、最佳固定准确率、重复运行优势与实际选择器表现。
\item \textbf{规模校准的诊断区分各类命题。}互补性判定把冻结选择器与最佳\emph{固定}成员交叉拟合，并以同代码克隆随机化零假设校准；模拟显示旧的 plug-in 对纯噪声错误支持，而校准规则保持名义水平，并按重复数如实报告功效（\S\ref{sec:diagnostics}）。
\end{enumerate}
决定性问题是：不同的生成程序能否在相同执行次数花在同一固定程序上之外，带来冻结选择收益，且这种优势能在独立重复中保留。一项新的预注册 MATH-500 采集恰好提供这一控制（\S\ref{sec:wp1r}）。在该面板上，增益位于声明的 $1$\,pp 界线之内，但由于覆盖缺口，形式上是 \textsc{Insufficient Evidence}（证据不足）而非强否定：克隆校准差为 $\WpVthreeD$\,pp（CI $\WpVthreeDCI$）。因此，稳定互补性仍是一个需在其他面板与领域上以更多重复检验的估计目标，而不是本面板已发现的性质。

这一边界为群体构造指出了一个更锐利的对象：有用的路由取决于分离执行噪声之后稳定的任务—harness 交互——这正是我们的诊断所要检验的估计目标。
