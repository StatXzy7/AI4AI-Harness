固定的推理预算应当用于更多程序，还是同一程序的更多次执行？自动化 agent 设计让第一种选择越来越容易实现：构建模型围绕固定求解器编写 LLM harness，安排提示、工具与控制流\citep{adas2024,tthe2026,selfharness2026}。这样的程序群体承载着一种分工设想：不同成员擅长不同任务。这一设想的实际价值，取决于程序优势能否持续，以及能否据此作出选择。

这种优势最先呈现的信号通常是额外覆盖：一个程序答对了另一个程序答错的题。然而，同一程序也会产生这种现象。两个成功概率均为 $0.5$ 的独立执行，可以以 $0.75$ 的概率覆盖一道题。Pass@$k$ 刻画这种机会；self-consistency 和采样投票集成则将多次尝试聚合为一个答案\citep{chen2021codex,selfconsistency2022,moreagents2024}。因此，即使每个成员的代码完全相同，看到全部结果的 oracle 也能从群体中获得增益。重复次数较少时，选择最大的成功率估计，仍可能选中幸运的结果。

本文研究这一初始覆盖信号如何进一步体现为有用的任务专长。分析围绕三个问题展开：群体是否提供额外的正确答案？任务上的优势能否在新一次执行中重现？能否在执行前选出有帮助的程序，其覆盖又如何与固定程序的额外尝试比较？每个问题都将分析推进一步，接近如何分配推理预算这一实际决策。

核心实验在固定成员数和重复次数的同时改变程序身份。八个生成 harness 加上 \bare{}，与九个逐字节相同的基线槽位在相同的 $\RcvPairedN$ 道 MATH-500 题上分别执行三次。两次重复用于确定逐题选择，第三次检验选择能否迁移。随后，在开发数据上冻结的选择器根据题目特征作出选择，等执行次数重放则比较不同预算下可获得的答案。完整的 $35$ 个生成程序提供初始的单次覆盖图景。补充的 BIRD 轨迹将程序差异追踪到执行过程，展示实现与触发如何塑造评分背后的行为。

结果形成了一条连贯的证据链（图~\ref{fig:sampling-control}）。相同程序产生正的 oracle 余量；生成程序确实具有更强的评分模式可重复性，但持续损失涉及 $\RcvLossTasks$ 道题，持续获胜仅出现在一道题上。这种结构更清楚地描绘了弱点，而非有用的任务优势：克隆校准后的留出收益为 $\RcvD$ 个百分点，冻结选择器收益为 $\RcvPolicyGain$ 个百分点，两臂在 $27$ 次执行时均达到 $\RcvReplayFullCoverage\%$ 的 oracle 覆盖。

本文提供了用于解释 oracle 余量的同代码参照、区分持续损失与获胜的重复执行分析，以及冻结选择与等执行次数覆盖的联合视角。它们共同将程序群体的价值具体化：增加了哪些答案，哪些差异能够持续，以及哪些优势能够帮助作出实际选择。
