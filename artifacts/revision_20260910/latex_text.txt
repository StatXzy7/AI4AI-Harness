BEHAVIORAL COLLAPSE IN AI-GENERATED HARNESS
POPULATIONS
Anonymous authors
Paper under double-blind review
ABSTRACT
Automatically generated LLM harnesses can differ in source code, executed
mechanisms, and correctness outcomes. These differences need not imply re-
producible additional capability. We examine the distinction on BIRD text-to-
SQL. A discovery population had 36 of 91 harness pairs identical on all evalu-
ated outcomes despite distinct source code; trace inspection found absent mech-
anisms, untriggered branches, and broken multi-turn paths. A subsequent facto-
rial study crossed strategy forcing and an admission gate over six builders and
three seeds, using 1,169 questions and the official BIRD scorer. Free genera-
tion already yielded 8.6 pp observed oracle headroom. Post-review reanalysis of
the archived experiment estimates the combined intervention at −0.16 pp (95%
CI [−0.83, +0.87]), with no clear improvement. The implemented gate also ex-
cludes two allowed prompt-level strategy types, so this contrast cannot isolate
verification alone. Repeated executions show outcome instability, which a single-
run oracle can exploit without stable mechanism complementarity. We distinguish
observed headroom from stable task–harness advantages and identify the controls
needed to connect either to usable selection gains. The current evidence estab-
lishes these measurement limits; it does not yet identify stable complementarity
beyond repeated sampling.

INTRODUCTION
An LLM harness is the program of prompts, tools, and control flow that wraps a frozen model.
Automatically generating many such programs creates an evaluation problem: what evidence shows
that a new program provides a new capability? Different source code may execute the same path;
different paths may produce the same answer; different answers on one run may reflect execution
randomness rather than a repeatable advantage.
We study this problem on BIRD text-to-SQL (Li et al., 2023). In a Phase-I discovery population, 21
of 66 generated-candidate pairs had identical correctness vectors. Including the shipped react har-
ness and bare baseline gives 36 identical pairs out of 91. Pairwise code similarity had no observed
rank association with outcome disagreement (ρ = −0.01). Trace inspection found three distinct
situations: claimed mechanisms absent from control flow, mechanisms present but untriggered on
the inspected tasks, and broken multi-turn implementations. These observations motivate an audit
of the measurement process; they do not establish that generated harnesses generally collapse.
A subsequent pre-specified factorial study crossed strategy forcing and conformance gating over six
builders and three seeds. Its primary evaluation used 1,169 questions from nine databases outside
protocol development, with one disclosed 18-item smoke-test exception. Under this revised setting,
free ungated generation already produced 8.6 pp observed oracle headroom. The Phase-I pattern
therefore did not recur, but changes in generation, judge, data, and execution prevent attribution to
any one protocol component without a controlled bridge.
The original gate also changes the admissible strategy space: two allowed single-call prompt trans-
formations cannot pass its mechanism check. Consequently, the intervention combines mechanism
screening with verification. We preserve that experiment and report a versioned post-review reanal-
ysis rather than treating it as a repaired-gate trial. The primary contrast remains −0.16 pp (95%
CI [−0.83, +0.87]). This unresolved estimate neither demonstrates improvement nor establishes
equivalence.

RELATED WORK
2.1
HARNESS GENERATION FOR LLMS
A growing line of work generates task-specific scaffolding around a frozen model. TTHE evolves
text-to-SQL harnesses with an LLM proposer/judge loop (Nie et al., 2026); Self-Harness (Zhang
et al., 2026b) shows a model can improve its own harness; JIT-Agent (Zhang et al., 2026a) trains
a model to generate a harness per task at inference time; Task-CoEvolve (Miyai et al., 2026) co-
evolves tasks and scaffolds. A concurrent 2026 cluster makes harness evolution behavior-aware
from the verification side: HarnessLens (Xu et al., 2026) allocates rollout budget using behavior-
level checks during evolution; HarnessFix (Chen et al., 2026) repairs harnesses from trace-grounded
diagnoses; AHE (Lin et al., 2026) verifies each proposed edit against self-declared behavioral pre-
dictions; gated semantic quality-diversity search (Luo et al., 2026) evolves populations over LLM-
assigned pathology descriptors; Harness Handbook (Wang et al., 2026) attacks behavior localization
and outer-loop search.
Our work is complementary but distinct in unit of analysis and question. Table 1 contrasts the two
nearest systems. HarnessLens uses behavior as a signal inside an evolution loop to allocate compute;
we ask whether the resulting population is behaviorally diverse as an outcome property, and how
it changes under generation-side interventions. HarnessBank (Luo et al., 2026) documents search-
space collapse and maintains a semantic diversity library with gated screening; our conformance
gate does not score semantics at all — it verifies mechanically, via counterfactual trace probes, that
a declared mechanism executes — and our design compares admission policies through a factorial
contrast. Because the implemented gate also excludes allowed prompt transformations, the current
experiment does not isolate verification’s causal contribution.

2.2
HARNESS CONDITIONAL UTILITY AND ROUTING
Harness quality is instance-conditional: Gupta et al. (2026) and Cho (2026) document that no single
harness dominates across instances. HELIX evaluates a full sibling-harness outcome matrix and
portfolio complementarity beyond the best fixed candidate, listing a router as future work (Fan &
Huang, 2026). STS routes over six fixed human-designed scaffolds (Zhou et al., 2026); GRASP
gates skill edits into a development-time library (Moll et al., 2026); Kim (2026) learn instance-level
routing over {no-search, search, abstain}; Liu et al. (2026) route models within a harness. Classical
algorithm selection (Rice, 1976) and portfolio solvers such as SATzilla (Xu et al., 2008; Kotthoff,
2014) select enumerated algorithms from instance features.
Our candidates are complete automatically generated harnesses. We measure the population out-
come structure a selector would inherit (§5.4), rather than build a selector. We diagnose execu-
tion paths and compare generation policies through a factorial whose treatment includes structural
screening; the present study does not establish stable selectable value.
2.3
BEHAVIORAL DIVERSITY IN LLM POPULATIONS
Diversity of LLM outputs has mostly been studied at the sample level (self-consistency, diverse
decoding) or the agent-policy level. The observation that syntactically distinct programs can exhibit
identical behavior echoes coverage gaps documented in program synthesis and mutation-testing
practice; our contribution is to instantiate and quantify it for AI-generated harness populations, with
a mechanism-level taxonomy.

PHASE I: MEASURING AND DIAGNOSING THE COLLAPSE (DISCOVERY)
Phase I is a discovery study: its role is to establish the phenomenon, the taxonomy, and the exis-
tence of task-side headroom, and to motivate the confirmatory design. None of its results is confir-
matory: 24 of its 151 evaluation items overlapped protocol-development measurements, the human
control was designed after inspecting development traces, and its judge was a conservative proxy
(Appendix A). We report it with those limits stated.
3.1
HARNESSES, OUTCOMES, AND THE THREE METRICS
A harness H wraps a frozen target model M: it receives the natural-language task x, issues one or
more calls to M, optionally executes intermediate artifacts (e.g. SQL), and returns a final answer
scored programmatically. With H0 the bare single-call baseline and Y ∈{0, 1} correctness, the
harness marginal value is ∆(x, H, M) = Y (x, H, M) −Y (x, H0, M) ∈{−1, 0, +1} (+1 repair,
−1 harness-induced harm).
We propose that harness-generation and harness-routing pipelines report three precondition metrics
on a held-out set, all computable from the outcome matrix any evaluation already produces: (i)
pairwise outcome disagreement — over all harness pairs, the fraction of tasks where correctness
differs; (ii) union repair rate — the fraction of bare errors some population member repairs; (iii)
bare-inclusive oracle headroom

3.3
TRACE TAXONOMY: WHY CODE DIVERSITY FAILS TO BECOME BEHAVIORAL DIVERSITY
Auditing execution traces (the sequence of LLM calls and artifact executions per task) decomposes
“different code” into three failure classes:
• T1 — mechanism described, not executed (6/12 candidates). The harness issues ex-
actly one LLM call and never executes an artifact — the identical execution path as bare.
Docstrings claim retrieval, self-checking, or token caps; none exists in the control flow.
• T2 — mechanism present but untriggered (react, 10/10 audited tasks). The first SQL
executes successfully, so error repair is not triggered and the final SQL equals bare’s. This
does not show that repair feedback lacks a causal path when a failure occurs.
• T3 — broken multi-turn path (1/12). The one candidate implementing genuine multi-
turn repair returns prose as final SQL, converting bare-correct items into harness-wrong.
The taxonomy is actionable: T1 demands an execution-path acceptance gate, T2 demands controlled
faults to test trigger and feedback use, T3 demands executable-output validation — all generation-
protocol requirements.

PHASE-I PROTOCOL PROBES AND THEIR LIMITS
Phase I also probed generation-side fixes — a strategy-forced free-form protocol (assigned mech-
anism, import/smoke acceptance) and a compiled Harness IR. Under the strategy-forced protocol
two of three builders produced populations whose point estimates exceeded the pre-specified thresh-
olds (Qwen3.8-Flash 5.96, DeepSeek-V4-Flash-Vision-Exp 7.95 pp; the old-protocol arm missed at
4.64 pp), and per-strategy acceptance ordered with builder identity (GLM-5.3-Flash 3/8, Qwen3.8-

Phase II but are not confirmatory, for three disclosed reasons: the design was two nested contrasts
that cannot separate protocol from builder main effects; the early runs lack per-attempt logs, so bud-
get equality cannot be audited; and acceptance was an import/smoke check, not the counterfactual
conformance gate of §4. Full condition details are in Appendix A.
Generation-null failures (M0).
Re-running the original optimize loop with Qwen3.8-Flash and

distinct-source day-1 population.

PHASE II: CONFIRMATORY GENERATION STUDY (DESIGN)
Phase II is the confirmatory study. Its protocol was frozen and committed before any confirma-
tory outcome was observed (one exception, disclosed as deviation D1 in the protocol changelog: an
18-item pipeline smoke test whose aggregate accuracies were observed and whose items were re-
tained); deviations are logged in the protocol changelog (Appendix B). The frozen estimand, splits,
instruments, and analysis plan are summarized here.
4.1
DESIGN
Arms.
Two crossed factors: strategy forcing (S=1: the builder is assigned a named mechanism
from a fixed set of eight; S=0: the builder invents an improvement with no mechanism named) and
the conformance gate (G=1: the harness must pass the frozen conformance suite; G=0: neutral va-
lidity only). This yields four factorial arms, which we denote II-A (free/ungated), II-B (free/gated),
II-C (forced/ungated), II-D (forced/gated). A fifth, pre-specified secondary arm II-E (open mecha-
nism discovery: the builder emits a self-specified behavioral contract over generic trace primitives,
gated on its own declaration) tests whether mechanism diversity requires author-supplied vocabu-
lary at all; it is deliberately outside the factorial. These arm names are Phase-II-specific; Phase-I
conditions in §3.5 are always referred to with their descriptive names.

Judge.
Primary: the official BIRD execution scorer (set equality on raw result rows, 30 s wall-

Instruments.
The conformance suite drives each harness against scripted scenarios and asserts on
the recorded execution trace, never on task performance, so gating cannot leak outcome supervision.
Every mechanism is probed with paired counterfactual variants whose correct answer differs — in-
cluding a variant where the first query succeeds, separating conditional repair from an unconditional
second call — and answers are compared by exact normalized equality. The suite was calibrated
before any Phase-II generation against three hand-written positive controls (all must pass) and two
known-negative impostor harnesses (both must be rejected), plus the invariant that the bare baseline
must violate every conditional property; the calibration is an executable gate re-run before each gen-
eration batch. Arm II-E additionally enforces non-vacuity (the contract must be violated by the bare
baseline, checked by running it) and verifies only the properties actually asserted.

4.2
FROZEN ANALYSIS PLAN
The primary estimand is the paired difference in bare-inclusive oracle headroom, H(II-D) −
H(II-A) over (builder × seed) cells, on the full 1,169-question set under the official judge — a
continuous effect with a two-sided 95% CI and paired permutation test, never a pass/fail threshold.
The Phase-I thresholds survive only as a descriptive checklist. Confirmatory secondaries (Holm-
corrected, all four arms on the same core-400 items): gate main effect [(B−A) + (D−C)]/2, strat-
egy main effect [(C−A) + (D−B)]/2, and their interaction (D−C) −(B−A) — whether strategy
differentiation requires execution fidelity to be realized. Original plan and corrected inference:
the original primary code omitted within-database task resampling and sampled tasks separately
across cells; the factorial code resampled cell summaries only. The versioned post-review analysis
uses 10,000 shared database/within-database task draws across all arms and cells, keeping builders
fixed and resampling generation seeds within builder. It does not add execution-repeat variance.
Exact sign-flip reference tests are conditional on observed tasks and on cell-contrast sign symme-
try (one-sided primary; two-sided secondaries with Holm adjustment). These are not randomized
causal tests. H(P) is not monotone in K — adding a harness that answers everything correctly
drives headroom to zero — so matched-K comparison, not monotonicity, licenses cross-population
claims. K-matched sensitivity, the full estimand definitions, and the robustness audits (dual judge,
cache-off replication, repeat stability) are specified in Appendix B together with the protocol devia-
tion log.

PHASE II: RESULTS
5.1
CORRECTED REANALYSIS OF THE ORIGINAL GATE EXPERIMENT
The following tables report a post-review reanalysis of archived outcomes, not a new experiment
with a repaired gate. Original analysis files remain available. All revised tables use full-precision
outcomes from one canonical input order; the four-arm analysis reuses the same bare records on the
same 400 tasks. The revised intervals use shared database and within-database task draws across all
arms and cells, with generation seeds resampled within each of the six fixed builders.
The paired estimate is −0.16 pp with unadjusted 95% CI [−0.83, +0.87] and one-sided sign-flip
p = 0.647. We find no clear improvement; the interval does not establish equivalence. The full-set
cell contrasts range from −4.36 to + 2.74 pp. These are estimates for the implemented screening
policy, which excludes some allowed strategies, rather than a pure verification intervention.
5.2
FACTORIAL EFFECTS AND ABSOLUTE PERFORMANCE
The gate estimate is −0.69 pp; its Holm-adjusted p = 0.079 does not meet the 0.05 threshold.
This cannot distinguish useful verification from the gate’s structural exclusion of prompt transfor-
mations. The corrected fixed-K gate sensitivity is −0.31 pp (95% CI [−1.07, +0.40]). Both sides

6
DISCUSSION AND CONCLUSION
What the evidence establishes. Source diversity, executed mechanisms, and one-run correctness
differences are distinct measurements. The Phase-I pattern did not recur in the revised Phase-II
setting; multiple protocol changes prevent identifying the cause. The corrected analysis of the orig-
inal gate shows no clear headroom improvement. Because that gate also excludes allowed prompt
strategies, it does not identify the effect of verification alone.
What remains unidentified. Same-code reruns can disagree and create oracle gains. Outcome
flip rates measure instability, not the standard error of a treatment contrast, and cannot define a
numerical noise floor for that contrast. A matched-cost clone control, independent repeat validation,
and calibration covering all admitted mechanism types are needed before attributing headroom to
stable additional capability.
Limitations. The main comparison uses one text-to-SQL target and six fixed builders, with three
generation seeds per builder. Phase I is discovery evidence with disclosed task overlap, a proxy
judge, and a post-trace human control. The new statistical analysis is post-review and does not add
independent executions. K-matched and R2 results now share the corrected data and resampling
chain. W1/W3 now share the canonical data but remain descriptive; selection uncertainty and in-
dependent utility validation are outstanding. The completed one-seed MATH-500 free-arm probe
(Appendix G) extends the observed outcome comparison to a second domain, but does not supply a
clone control, a repaired-gate factorial, or an independent test of stable complementarity.
Generated code, observed outcome diversity, and reproducible additional capability should be eval-
uated separately. Our archived experiments expose failures at the first two levels and leave the third
unresolved. Reporting absolute oracle accuracy, best-fixed accuracy, admission policy, execution
cost, and repeat variability makes that boundary inspectable. Establishing practical value requires
independently validated selection gains beyond same-code repeated sampling.

Rich fingerprints.
To isolate the loader change, the W3 reanalysis retains the legacy lossy SQL
text transform: semicolon deletion, backtick replacement, lowercasing even segments after splitting
on single quotes, and whitespace joining. This is not a SQL parser or semantic normalization; it
can alter literals and quoted identifiers. Among 364,428 pair–task observations with two identical,
nonempty transformed SQL strings, 0 have different verdicts. This is an observed consistency check,
not a property guaranteed by construction.
Pair-level SQL dissimilarity averages (1−token-Jaccard) only over verdict-agreeing tasks with two
nonempty SQL strings. Its Spearman correlation with overall outcome disagreement is 0.597 across
4,386 within-cell pairs and 0.588 across 1,010 within-arm pairs. Pairs share candidates and tasks,
and the SQL metric conditions on verdict agreement; these correlations have no independence-based
significance or causal interpretation.
In R2’s 70-harness first cache-off acquisition, call counts change on 506/28000 comparisons and
verdicts on 2391/28000. Transformed SQL changes on 19569/27936 comparisons (70.05%); 64

mean token Jaccard among changed SQL pairs is 0.619. These channel-specific rates do not define
an effect-size noise floor. Canonical logical-call costs are reported separately in Table 6.

accuracy, uniform random subsets, greedy development oracle coverage, and greedy mean accuracy

split before its evaluation.

CROSS-DOMAIN REPLICATION: MATH-500 MINI-AUDIT
To test whether the Phase-II clean-protocol finding (free ungated generation produces distinct one-
run correctness vectors) is text-to-SQL-specific, we replicated the free-arm protocol on competition
math.
Protocol.
Six builders (the same models as Phase II), one seed, eight slots each, an R=3 raw-
attempt cap per slot, neutral validity gate (mechanism-blind: parse, import, interface, non-empty
answer on two dev questions). Frozen target GLM-5.3-Flash (same as the SQL study), temper-
ature 0. MATH-500 (Lightman et al., 2023): 500 tasks frozen before generation (100 dev / 400
eval, seed 20260908).
Judge: numeric equality where both sides parse as numbers (including
a/b, \frac{a}{b}, decimals), else normalized LaTeX string equality (units, base subscripts, ◦
stripped; \text{X} content preserved; pmatrix →tuple). Judge self-consistency: 400/400 gold
answers judge correct against themselves. bare accuracy 0.938 under the matched answer-format
instruction. Yield: 35/48 slots admitted (Rartifact 0.10–1.00; the two reasoning-heavy builders,
GLM-5.3 and Qwen3.8-Max, exhausted the 32k-token generation budget on reasoning before emit-
ting code in most slots — reported as-is). This is a replication probe, not a factorial: no strategy
forcing, no conformance gate.
Results (35 harnesses, 400 eval tasks).
Mean pairwise outcome disagreement 10.6% (max
33.0%), Keff 33/35 (0.94), outcome-identical pairs 0.7% — no trace of Phase-I-style collapse.
Union repair 76.0% of bare errors, union harm 0.8%, oracle headroom over bare 4.75 pp. Yet the best
fixed member is bare itself (0.9375; generated harnesses 0.68–0.87): observed oracle coverage ex-
ceeds bare while every generated member is worse individually. Repeated-execution and same-code
clone controls were not collected, so this does not establish stable complementarity or deployable
utility.
Two failure-side observations.
First, the clean-protocol diversity result replicates in a sec-
ond domain with a different output space.
Second, a quarantined pilot round (disclosed in
PROTOCOL CHANGELOG.md, entry G1) supplies an exploratory comparison: when the same six
builders were (mistakenly) given a GSM8K-style task description whose numeric answer format did
not match MATH-500, the generated population remained behaviorally diverse (16.2% disagree-
ment, Keff 19/19) while its union repair collapsed to 18% — and code-level inspection of the catas-
trophic members reproduced the Phase-I trace taxonomy verbatim (a generate-then-verify harness
whose verifier rejected nearly every answer and whose fallback returned the stale loop variable
or “0”). Diversity without utility, induced by a prompt-side protocol error invisible to code-level
checks: the measurement mandate, not any code-level audit, is what detects it.
Scope.
One seed, one target, no factorial, exploratory; the Phase-I collapse-inducing SQL protocol
was not re-run in the math domain, so this replication speaks to the clean-protocol result only, not
to the boundary of collapse.
