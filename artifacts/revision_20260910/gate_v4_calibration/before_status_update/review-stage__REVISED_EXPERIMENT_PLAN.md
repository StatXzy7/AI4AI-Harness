# 新版决定性验证方案（待预算与协议定稿，尚未运行）

版本：2026-09-10 draft v1。旧数据已被查看，本方案不追溯性宣称预注册。实施前须将下列所有选择、instrument测试结果、代码/数据/模型版本与预算写入实际freeze SHA；修正后的实验另建目录，不覆盖 Phase-II。

## 1. 一句话判断

值得继续，适合以离线诊断和受限推理验证推进：证明生成 harness 的新增优势能否在同代码重复采样、准入偏置和计算资源匹配后仍然保留；最大风险是把一次运行的 oracle 差异误当成稳定能力。

类别：测量信号质量、验证与计算分配；不新增训练模块。

## 2. 计算陷阱

不要先堆更多 builder、更多单次 target、更多 W3 相关性；这些不能识别执行随机性。3–5次重复是设计起点而非功效保证。旧的$3k/$15k/$26k预算方案已经与当前状态脱节，不作为报价依据。一次 harness invocation 可调用多个 solver，等K不等于等成本。先恢复已有调用数和token日志，按实际provider单价估算，缺失字段标记未知。

## 3. 核心可证伪问题与估计对象

在预定计算预算内，真实种群相对于同代码重复种群，是否提供可在独立重复中保留的任务特异性正确率增益？

同时报告：

- H_observed：每个运行块一次正确性矩阵的 oracle−best-fixed，统一含bare。
- H_stable：mean_x max_h p(h,x) − max_h mean_x p(h,x)，h集合含bare；有限重复的 plug-in max 有赢家偏差，不直接当无偏估计。
- Cross-repeat advantage：在repeat训练半部逐题选h*，在独立repeat验证半部评估；最佳固定h也只能从训练半部选择。训练/验证角色轮换后按任务/时间块保留依赖汇总。这个量是同题可重复优势，不是新题路由。
- 实际选择准确率：仅用独立开发任务训练/选择的规则，在从未用于该规则选择的新任务或新批次评估。区分于上述逐题 oracle。
- 绝对 oracle、best-fixed、bare、实际选择器、拒答/失败、solver调用、输入/输出token、延迟。

建议实践相关差异候选阈值为1.0 pp，仅用于精度模拟；最终阈值需依据使用场景在新执行前定稿。若CI仍宽于该范围，结论为不确定，不以不显著证明无效。

## 4. 已观察现象与替代解释

现有R3只有400题×bare×3次，R2只有选定A/D子集且重复不平衡；均已曝光，仅可做pilot或设计依据。它们支持存在执行随机性，不能给出完整种群的H_stable，也不能把D臂多收的一次重复与A臂单次作为平衡处理比较。

支持机制互补的证据：真实种群的独立重复优势大于clone，多个时间块/数据库方向一致，并在匹配成本后保留。推翻强主张的证据：差异在clone中同样出现、独立重复不保留、或只来自更多solver预算。

## 5. 零训练诊断与三张主图

先完成无需API的事项：完成W1选择不确定性推断（W1/W3描述性、K-matched/R2已完成canonical重算）、完整源码/运行时复原、新版gate的stub控制、重复层数据格式/种子规划、用既有噪声估计做simulation。simulation必须包含无机制差异null、存在固定h总体强弱但无任务交互、存在任务×h交互、时间块共同冲击和缓存耦合；检查假阳性、偏差、coverage、CI宽度，不用被观察的有利结果挑设计。

主图预定：

1. 真种群与clone：within-harness、between-harness及独立重复保留的优势，同图显示误差区间。
2. 同一raw pool：按机制分层的旧/新gate准入、误拒/误放，以及policy/fixed-K两个不同估计对象。
3. 固定资源曲线：相同预算网格下的绝对oracle、预冻结实际选择器、best-fixed、clone；不单以H为优化目标。

逐条日志至少包含target/provider模型标识、harness完整源码SHA256、task、arm、membership、raw候选/slot/attempt、repeat、clone identity、cache condition、独立run UUID、时间块与时间戳、随机化顺序、解码设置、调用/token/延迟、结果/judge版本、失败与中断原因、source file/line、冲突规则。clone源码与原件必须同哈希；仅调度身份不同，不能改prompt来伪装独立采样。

## 6. Oracle 与停止条件

先看固定成本下真实种群超出clone的oracle上界与独立重复优势。若上界已经没有实践价值，不开发学习型router。有限重复下max的乐观偏差通过独立repeat评估控制，不能只提高重复数后宣称已消除。

先做pilot精度模拟，再冻结样本量/重复数。不依据中间效应方向增加或停止确认性样本；若只能在预算内完成pilot，就标为pilot并诚实保留不确定性。

## 7. 最小改动 B：gate-v2 合同与校准

旧gate保留并命名screening-v1；不把NO_MECHANISM_declared直接改成PASS。

| 机制/变体 | 合同与检查 | 预期分类 |
|---|---|---|
| hint_guard 单调用 | 对有/无/变化Hint成对输入，spy观察solver请求中原约束被保留且有新增显式要求；不能依靠最后答对 | 合法prompt变换可通过 |
| format_guard 单调用 | 相同任务的格式指令有/无成对fixture；spy验证SQL fence/仅SQL输出请求及原schema约束保留 | 合法prompt变换可通过 |
| conditional repair | 首SQL成功不额外repair，注入错误时调用repair，改变反馈使后续请求/决策按合同变化 | 合法条件机制通过 |
| unconditional extra call | 成功/失败都执行第二次，不符合声明的条件分支 | 误实现拒绝 |
| read then discard | 读取反馈但后续请求/选择与扰动无关 | 已触发但信息未传递 |
| real majority vs select-first | 输入排列与多数答案翻转；输出遵循多数而非位置 | 多数通过、位置伪装拒绝 |
| non-triggered branch | 正常轨迹未触发时只标not_triggered；注入故障后另测 | 不凭正常路径认定无因果作用 |
| crashes / invalid output | 接口错误或返回非法类型 | execution_failure，单独报告 |

schema_link、decompose、two_view、error_classify等其余声明仍需分别列成可执行合同，不能以覆盖prompt两类冒充覆盖全部8类。每个合法类型至少有独立构造正例及相关负变体；控制集与benchmark分数隔离。校准作者/执行者与放行审核跨模型独立，报告逐类型混淆矩阵与fixture数量。未运行前不填误拒/误放率。

新raw pool：每slot严格先生成3份候选（不因早成功跳过），按预冻结顺序保存原字节与完整token账单；生成完并hash冻结，再离线应用neutral、screening-v1、gate-v2。生成与筛选必须解耦；旧日志缺少提前停止后的候选，不能恢复一个从未生成的完整pool。

Delta_policy：共同生成上限/共同raw pool下的准入与表现总差异，保留K=0。Delta_fixed-K：固定K的预定稀释敏感性，bare永远保留；K定义和随机抽样种子冻结。两者不同，不把差额解释成规模的因果中介比例。

## 8. 最小实验矩阵 A–D

| 工作包 | 最小设计 | 要排除的解释 | 尚待冻结 |
|---|---|---|---|
| A 精度pilot | 2个固定builder×2个新生成seed；每cell 2个harness+bare；200题；4个独立cache-off重复块 | 多次采样与任务特异性优势混淆 | builder/seed/task清单由hash规则而非结果选定；不称代表六builder |
| A clone | 每个真实cell有同K裸模型clone，以及dev选出的单harness clone；重复/时间分块与真实组配对 | bare过弱、代码相同但采样不同 | clone身份、run UUID和调用记录 |
| A 固定成本 | 对同一预冻结solver预算网格采集真实与clone轨迹，调度中只看剩余资源不看答题结果 | 等K但真实harness调用更多 | B网格、每调用上限、耗尽/截断/失败处理 |
| B | 同raw pool的neutral/v1/v2；全部合法机制控制集 | gate结构偏置、生成差异 | 合同、fixture、误放/误拒准则 |
| C | 固定一个builder、同target/题集/judge/cache/time-block；只改旧/新生成流程 | 跨阶段多重改动 | 旧流程恢复版本及可比接口 |
| D | 冻结一个简单选择规则；新生成批次或新数据库；random/top-accuracy/clone为对照 | 当前W1事后选择与过拟合 | 独立数据身份、选择规则、成本预算 |

A的等Kpilot若包含real、bare-clone、dev-fixed-clone三组：4 cells×200 tasks×4 repeats×3 members×3 groups=28,800 harness执行。不能把这个数当solver调用数或美元成本。真实组可能多调用，等K结果仅回答数量匹配问题；达到固定成本验收还需同预算网格的补充比较。若预算只支持更少项，先降低cells/tasks并将输出标pilot，不能保留原确认性措辞。

固定成本操作：事前为每任务/运行块定义相同输入/输出token预算及最大solver调用数；有统一计费记录的wrapper在请求前执行上限，低于下一次请求保留额度时停止并明确记录abstention/partial。真实组按预冻结顺序运行harness，clone组按相同资源约束重复单一代码。比较同一预算上限下的policy utility，并报告实际消耗差异，不宣称实际用量精确相同。截断规则是新实验处理的一部分，须同时报告未截断等K敏感性。

每task/block把三组交错或随机排列；不得分三天依次跑完三组。provider版本变化或服务失败须标block，不自动删掉低分块；failure可计入预定义策略utility并另报失败率。首次命中后停止评估会引入偏差，禁止。

## 9. 计算阶梯

- Tier0：现有数据重放、stub校准、precision/null simulation。停止扩张条件：仪器或对齐测试不通过、共同raw pool不可恢复、目标精度无合理预算。
- Tier1：完成上述pilot，只估计变异和可识别性；预先标明其曝光。若独立重复无法保留任何优势，转向有精度界限的负结果，不加router。
- Tier2：按模拟和预算冻结正式任务量及重复数，完成A+B；旧新桥接只做回答原因所需的最小配置。固定推断范围，加入repeat/time-block变异。
- Tier3：只有A+B已闭环才做D的一处独立边界验证；不做最大模型×所有消融。

## 10. 论文主线

Observation：代码不同、路径不同、单次正确性不同经常被混用。
Diagnosis：执行随机性、准入定义、数据冲突规则和资源改变各自能影响指标。
Mechanism：由受控故障注入与clone/重复对照辨别；没有证据的归因留空。
Method：一致合同＋canonical数据链＋重复/clone资源匹配审计。
Evidence：A/B主图，C桥接，D独立实用性；结果可正可负。
Conclusion：明确哪一种日常评估做法会误导决策，以及审计在何种范围可靠地纠正它。尚未完成该证据前，不使用暗示已分离稳定机制和噪声的标题式结论。

## 11. 终止或转向标准

1. 真实种群与clone差异不能在独立重复保留：撤回稳定互补主张。
2. 优势只来自更多计算或较弱best-fixed：撤回新增实际能力主张。
3. 正负机制控制无法可靠区分：gate只能报告为未校准筛选器，不作verification效果解释。
4. 精度达不到预定阈值：报告不确定，不声称等效/没有价值。
5. 独立D不复现：报告外推边界；不从其他seed/任务中择优替换。

## 16. 稳定能力识别检查：修正下一验证的比较对象

`STABLE_IDENTIFICATION.md`与`stable_identification.json`记录两个精确反例：独立验证超过发现集所选fixed可以为正而H_stable=0；两个policy witness下界相减不是H_stable差值下界。故第15节提出的条件验证只能保留为单独效用目标，不能用于关闭稳定新增能力要求。

下一验证必须保留全部固定成员，明确policy对真正best-fixed的witness与H_stable的下界关系；真实/clone差值采用[L_real−U_clone,U_real−L_clone]或其他经验证的正确方法，不减两个下界。保留不同bare的dev-code clone池也可能有稳定互补。新增Hoeffding联合概率带只是固定任务池、独立同分布时间块前提下的保守参照，范围很宽，不是正式主分析或样本量建议。

在继续条件目标功效模拟前，先落实完整runtime、独立执行/缓存核验及成本账本。A的跨运行/任务/数据库与预算匹配要求、B–D均不缩小。论文只更正对应解释，未加入新的实测结论。
